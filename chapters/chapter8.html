Глава 8: Стиль и эффективность

Стиль и эффективность

Чтобы хорошо программировать, нужно находить баланс между "сделать работу сейчас" и "сделать её правильно". Нужно уметь балансировать время, ресурсы и качество. Программы содержат ошибки. Программы требуют поддержки и расширения. Программы разрабатываются несколькими программистами. Красивый код без практической пользы бесполезен, но ужасный код без поддержки — это катастрофа в ожидании.

Опытные программисты понимают свои ограничения и пишут правильный код.

Чтобы хорошо писать на Perl, нужно понимать язык. Нужно также развивать чувство вкуса в программировании и дизайне программ. Единственный путь — практика: писать код, поддерживать его и читать хороший код. Быстрых путей нет, но есть ориентиры.

Как писать поддерживаемый Perl

Поддерживаемость — это измерение того, насколько легко понимать и изменять программу. Напишите код. Вернитесь к нему через полгода (или шесть дней). Сколько времени займёт исправление ошибки или добавление фичи? Это и есть поддерживаемость.

Поддерживаемость не измеряет, нужно ли вам вспомнить синтаксис встроенной функции. Она измеряет, насколько сложно другому опытному программисту понять ваш код.

  • Устраняйте дублирование. Ошибки часто скрываются в повторяющемся коде. Хорошо спроектированные системы имеют мало дублирования — используют функции, модули, объекты и роли для выделения повторяющихся частей.
  • Давайте хорошие имена сущностям. Ваш код рассказывает историю. Имена переменных, функций, модулей, классов и ролей могут прояснить или запутать смысл.
  • Избегайте ненужной хитроумности. Лаконичный код хорош, когда он делает намерения явными. Хитрый код скрывает намерения за трюками. Пишите понятные решения. Сложные решения — прячьте за простым интерфейсом и документируйте.
  • Приветствуйте простоту. Более простой код проще поддерживать. Простота — это фокус на самом важном.

Как писать идиоматичный Perl

  • Понимайте мудрость сообщества. В Perl живые споры о стилях и техниках. Слушайте их.
  • Следуйте нормам сообщества. Используйте инструменты сообщества: Perl::Critic, Perl::Tidy, CPAN::Mini, Carton, Pinto и другие.
  • Читайте чужой код. Присоединяйтесь к сообществам, например, Perl Beginners. Читайте код, задавайте вопросы.

Как писать эффективный Perl

  • Пишите тестируемый код. Хорошая тестовая база укрепляет дизайн и уверенность в изменениях.
  • Модульность. Поддерживайте инкапсуляцию, правильно проектируйте интерфейсы между компонентами.
  • Следуйте внятным стандартам кодирования. Согласованные правила помогают разработчикам понимать код друг друга.
  • Используйте CPAN. CPAN — это усилитель возможностей. Ищите готовые решения прежде, чем писать своё.

Нашли баг? Сообщите о нём. Исправьте его, если можете. Отправьте тест. Поблагодарите авторов. И, когда будете готовы — поделитесь своим кодом.

Исключения

Хорошие программисты ожидают неожиданное: пропавшие файлы, переполненные диски, падения сети или базы данных.

Perl обрабатывает исключения с помощью механизма динамической области видимости. Надёжные программы должны правильно обрабатывать исключения: попытаться восстановиться, или корректно зафиксировать проблему.

Генерация исключений

Пример: открытие лог-файла с выбрасыванием ошибки при неудаче:


sub open_log_file {
    my $name = shift;
    open my $fh, '>>', $name or die "Can't open log to '$name': $!";
    return $fh;
}

Функция die() устанавливает переменную $@ и немедленно завершает выполнение текущей функции, выбрасывая исключение. Если исключение никто не перехватывает, программа завершится с ошибкой.

Механизм обработки исключений использует динамическую область видимости, такую же, как и local переменные.

Обработка исключений

Иногда полезно позволить исключению завершить программу. Например, процесс может выбросить исключение при переполнении логов, что приведёт к отправке SMS администраторам. Другие исключения могут быть не фатальными — программа может восстановиться. Или можно успеть сохранить работу пользователя перед выходом.

Используйте блочную форму оператора eval для перехвата исключений:


# лог-файл может не открыться
my $fh = eval { open_log_file('monkeytown.log') };

Если файл открылся успешно, $fh будет содержать файловый дескриптор. В случае ошибки $fh останется неопределённым.

Аргумент-блок для eval создаёт новую область видимости, как лексическую, так и динамическую. eval поймает любое исключение, выброшенное внутри этого блока.

Чтобы проверить, поймано ли исключение, проверяйте переменную $@. Обязательно локализуйте $@ перед использованием:


local $@;
my $fh = eval { open_log_file('monkeytown.log') };
if (my $exception = $@) { ... }

Сразу копируйте $@ в лексическую переменную, чтобы избежать его перезаписи другим кодом.

Например, обрабатываем ошибку открытия файла:


if (my $exception = $@) {
    die $exception unless $exception =~ /^Can't open logging/;
    $fh = log_to_syslog();
}

Для большей надёжности можно выбрасывать исключения не строками, а ссылками (возможно, благословленными), чтобы передавать больше информации.

Модуль Exception::Class упрощает создание и использование объектов-исключений:


package Zoo::Exceptions {
    use Exception::Class
        'Zoo::AnimalEscaped',
        'Zoo::HandlerEscaped';
}

sub cage_open {
    my $self = shift;
    Zoo::AnimalEscaped->throw unless $self->contains_animal;
    ...
}

sub breakroom_open {
    my $self = shift;
    Zoo::HandlerEscaped->throw unless $self->contains_handler;
    ...
}

Также хорошим выбором является Throwable::Error.

Предостережения по работе с исключениями

Хотя выбрасывать исключения просто, правильно их ловить — сложнее. При работе с $@ возможны подводные камни:

  • Нелокализованный $@ может быть перезаписан другим eval в том же динамическом контексте.
  • $@ может содержать объект, который в логическом контексте ведёт себя как false.
  • Обработчики сигналов (особенно DIE) могут изменять $@.
  • Деструкторы объектов при выходе из области видимости могут вызвать eval и изменить $@.

Модуль Try::Tiny делает перехват исключений безопаснее и удобнее:


use Try::Tiny;

my $fh = try { open_log_file('monkeytown.log') }
catch { log_exception($_) };

try заменяет eval. Блок catch выполняется только при наличии исключения, которое передаётся в $_.

Встроенные исключения

Сам Perl выбрасывает некоторые исключения. См. perldoc perldiag для списка фатальных ошибок, которые можно перехватить во время выполнения:

  • Использование недопустимого ключа в заблокированном хеше
  • Благословление неблагословленной ссылки
  • Вызов метода на недопустимом объекте
  • Отсутствие метода у объекта
  • Использование грязных данных в небезопасной операции
  • Модификация неизменяемого значения
  • Неверная операция над ссылкой

Также можно перехватывать исключения, генерируемые autodie или поднятые предупреждения.

Прагмы

Большинство модулей Perl предоставляют функции или классы. Прагмы (например, strict или warnings) изменяют поведение языка. Их имена пишутся в нижнем регистре.

Прагмы и область видимости

Прагмы работают в пределах лексической области:


{
    {
    }
    use strict;
    my $lexical = 'доступен здесь';
}

Эффект прагмы сохраняется в дочерних областях.

Как использовать прагмы

Прагмы подключаются так же, как обычные модули, и могут принимать аргументы:


use strict qw(subs vars);
use Modern::Perl '2014';

Чтобы отключить эффект прагмы в локальной области, используйте no:


use Modern::Perl;
{
    no strict 'refs';
    # работа с таблицей символов
}

Полезные прагмы

  • strict — строгая проверка ссылок и переменных
  • warnings — выдача предупреждений
  • utf8 — поддержка исходников в UTF-8
  • autodie — автоматическая проверка ошибок системных вызовов
  • constant — создание констант во время компиляции
  • vars — объявление глобальных переменных пакета
  • feature — включение/выключение новых возможностей Perl
  • experimental — включение экспериментальных функций
  • less — демонстрация написания собственных прагм

Вы можете писать собственные прагмы на чистом Perl. См. perldoc perlpragma и perldoc perlvar для подробностей о переменной $^H.

Прагмы из CPAN

  • autovivification — отключение автосоздания элементов
  • indirect — запрет косвенных вызовов методов
  • autobox — добавление объектного поведения базовым типам
  • perl5i — объединение множества новых возможностей Perl

Хотя эти инструменты пока используются ограниченно, они полезны и экспериментальны. Например, autovivification и indirect помогают писать более корректный код.
