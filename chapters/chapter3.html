Глава 3: Управляющие структуры

Язык Perl представляет собой сочетание нескольких отдельных элементов. В отличие от естественных языков, где можно использовать нюансы тональности и интуицию для передачи смысла через пробелы в знаниях, компьютерам и исходному коду требуется точность.

Вы можете писать эффективный Perl-код без углубления во все детали языковых особенностей, но понимание их взаимодействия необходимо для написания хорошего кода.

Имена (identifiers)

Имена встречаются повсюду в Perl-программах: вы выбираете их для переменных, функций, пакетов, классов даже файловых дескрипторов. Допустимые имена в Perl начинаются с буквы или подчеркивания и могут содержать комбинации букв, цифр и подчеркиваний. Если активировано pragma utf8 (Unicode и строки, стр. 28), можно использовать любые UTF-8 символы:


my $name;
my @_private_names;
my %Names_to_Addresses;
sub anAwkwardName3;

# при активации use utf8; 
package Ingy::Döt::Net;

Недопустимые имена:


my $invalid name; # пробел недопустим
my @3; my %~flags; # нельзя начинать с символа или цифры 
package a-lisp-style-name;

Имена переменных и сигили (sigils)

Переменные всегда имеют ведущий знак, определяющий их тип. Скалярами ($), массивами (@) и хэшами (%) соответственно:


my $scalar;
my @array;
my %hash;

Сигили разделяют переменные в разных пространствах имён. Например, можно объявить несколько переменных с одинаковым именем, но разными типами:


my ($bad_name, @bad_name, %bad_name);

Пространства имён (Namespaces)

Perl позволяет группировать связанные функции и переменные в уникальное пространство имён. Например:


package DessertShop::IceCream;

Символы двойного двоеточия :: используются для иерархии. Обращение к членам вне пространства требует полной квалификации:


DessertShop::IceCream::add_sprinkles()

Пространства имён глобальны. Важно следовать соглашениям: пакеты с нижнего регистра резервируются для системных модулей (например, strict), пользовательские начинаются с заглавной буквы.

Переменные

Переменная в Perl — это место хранения значения. Хотя простейшие программы могут работать напрямую со значениями, большинство настоящих программ используют переменные. Подобно алгебре: вы оперируете символами для описания формул. Проще объяснить теорему Пифагора через переменные a, b и c, чем перечислять все возможные тройки чисел.

Область видимости переменных

Ваш доступ к переменной определяется её областью видимости. В современном Perl переменные чаще всего имеют лексическую область видимости, зависящую от структуры кода. Обычно область создаётся блоком в фигурных скобках { } или целым файлом.

Объявление package без блока не создаёт новую область видимости:

package Store::Toy;
my $discount = 0.10;
package Store::Music;
# $discount всё ещё видно
say "Our current discount is $discount!";

Но если использовать блок {}, появляется новая область видимости:

package Store::Toy {
    my $discount = 0.10;
}
package Store::Music {
    # $discount здесь уже не видно
}
package Store::BoardGame;
# $discount всё ещё недоступно

Значки переменных (Sigils)

Значок (sigil) переменной определяет её тип: скаляр ($), массив (@), или хеш (%). При доступе к данным значок может меняться в зависимости от операции:

@values    # весь массив
$values[0] # один элемент массива
@values[@indices] # срез массива

Присваивание массива через срез:

@values[@indexes] = some_function();

Или получение одного элемента в скалярном контексте:

my $element = @values[@indices];

Анонимные переменные

Переменные в Perl могут быть анонимными (без имени). Доступ к ним возможен только через ссылки.

Переменные, типы и приведение типов

Переменная в Perl — это контейнер и значение одновременно. Тип контейнера (скаляр, массив, хеш) неизменен, но тип значения может меняться. Это может привести к приведению типов при операциях.

Например, чтобы узнать количество элементов в массиве:

my $count = @items;

Значения

Переменные позволяют абстрактно работать с данными. Значения делают программы конкретными и полезными: имя вашей тёти, адрес, расстояние до лунного гольф-клуба и так далее. Формат данных в программе, как правило, строго регламентирован.

Строки

Строка в Perl — это текст или бинарные данные без строгой структуры. Строка приобретает смысл, только если вы его задаёте. Литералы строк обычно заключаются в одинарные или двойные кавычки:

my $name = 'Donner Odinson, Bringer of Despair';
my $address = "Room 539, Bilskirnir, Valhalla";

В одинарных строках экранируются только апострофы и обратные слэши:

my $reminder = 'Don\'t forget to escape ' . 'the single quote!';
my $exception = 'This string ends with a ' . 'backslash, not a quote: \\';

Пример экранирования с использованием Test::More:

use Test::More;
is 'Modern \\ Perl', 'Modern \\\\ Perl', 'single quotes backslash escaping';
done_testing();

Двойные кавычки позволяют вставлять спецсимволы:

my $tab = "\t";
my $newline = "\n";
my $carriage = "\r";
my $formfeed = "\f";
my $backspace = "\b";

Разные способы записи строк:

my $escaped = "two\nlines";
my $literal = "two
lines";

is $escaped, $literal, 'equivalent \n and newline';

Объединение строк оператором .:

my $kitten = 'Choco' . ' ' . 'Spidermonkey';

Интерполяция переменных в двойных кавычках:

my $factoid = "$name lives at $address!";
# Эквивалентно
my $factoid = $name . ' lives at ' . $address . '!';

Чтобы вставить двойные кавычки в строку:

my $quote = "\"Ouch,\", he cried. \"That hurt!\"";

Для удобства можно использовать операторы q и qq

Расширенные строки и heredoc

Для создания строк можно использовать оператор q или qq с различными разделителями:

my $quote = qq{"Ouch", he said. "That hurt!"};
    my $reminder = q^Don't escape the single quote!^;
    my $complaint = q{It's too early to be awake.};

Также Perl поддерживает конструкцию heredoc для присваивания многострочного текста переменной:

my $blurb =<<'END_BLURB';
    He looked up. "Change is the constant on which they all
    can agree. We instead, born out of time, remain perfect
    and perfectly self-aware. We only suffer change as we
    pursue it. It is against our nature. We rebel against
    that change. Shall we consider them greater for it?"
    END_BLURB

Синтаксис heredoc состоит из трёх частей: двойные угловые скобки <<, тип кавычек (одинарные или двойные), и уникальный идентификатор, завершающий текст. Завершающая метка должна стоять в начале строки без пробелов.

Пример использования heredoc внутри функции:

sub some_function {
        my $ingredients =<<'END_INGREDIENTS';
    Two eggs
    One cup flour
    Two ounces butter
    One-quarter teaspoon salt
    One cup milk
    One drop vanilla
    Season to taste
    END_INGREDIENTS
    }

Heredoc и отступы

Если в идентификаторе после << есть пробел, то и завершающая метка должна содержать аналогичный пробел. Однако Perl не удаляет отступы в самом тексте heredoc, что иногда может вызвать сюрпризы.

Юникод и строки

Unicode — это система кодирования символов всех письменных языков мира. Строки Perl могут быть двух типов:

  • Последовательность символов Unicode (каждый имеет свой кодпоинт);
  • Последовательность октетов (8-битных чисел от 0 до 255).

Важно различать представление данных: память (октеты) и символы (Unicode).

Кодировки символов

Unicode-строка — это набор октетов, сопоставляемых символам по определённой кодировке, например UTF-8. Некоторые кодировки поддерживают только часть символов (ASCII, Latin-1).

Perl версии 5.16 поддерживает Unicode 6.1, версии 5.18 — 6.2, 5.20 — 6.3, 5.22 — 7.0.

Всегда декодируйте входные данные и кодируйте выходные данные в нужную кодировку!

Юникод в файловых дескрипторах

Пример открытия файла с автоматической декодировкой UTF-8:

open my $fh, '<:utf8', $textfile;
    my $unicode_string = <$fh>;

Или через binmode для существующего дескриптора:

binmode $fh, ':utf8';
    my $unicode_string = <$fh>;
    binmode STDOUT, ':utf8';
    say $unicode_string;

Модуль utf8::all позволяет применить UTF-8 ко всем файловым потокам сразу, но требует понимания работы с Unicode.

Юникод в данных

Для конвертации данных используйте функции модуля Encode:

use Encode;
    my $from_utf8 = decode('utf8', $data);
    my $to_latin1 = encode('iso-8859-1', $string);

Юникод в исходном коде программ

Чтобы использовать Unicode прямо в исходниках Perl, подключите прагму utf8:

use utf8;
    sub £_to_¥ { ... }
    my $yen = £_to_¥('1000£');

И обязательно сохраните файл в UTF-8!

Юникодные escape-последовательности

В двойных кавычках можно указывать символы через \x{}:

my $escaped_thorn = "\x{00FE}";

Или использовать имена символов через прагму charnames:

use charnames ':full';
    use Test::More tests => 1;
    my $escaped_thorn = "\x{00FE}";
    my $named_thorn = "\N{LATIN SMALL LETTER THORN}";
    is $escaped_thorn, $named_thorn, 'Thorn equivalence check';

Неявные преобразования

Большинство проблем с Unicode в Perl связано с тем, что строки могут быть либо октетами, либо символами. При неявных преобразованиях Perl иногда неожиданно интерпретирует октеты как Latin-1.

Это приводит к скрытым багам, особенно если в тексте только английские символы без диакритики.

Запомните: лучше всегда явно указывать кодировку данных на входе и выходе!

Modern Perl

my $hello = "Hello, ";
my $greeting = $hello . $name;

Если переменная $name содержит Alice, проблем не возникнет: представление в Latin-1 совпадает с UTF-8. Если же $name содержит José, возможны три варианта:

  • $name содержит четыре Unicode-символа.
  • $name содержит четыре октета Latin-1, представляющие символы Unicode.
  • $name содержит пять UTF-8 октетов для тех же символов.

Литерал строк может быть:

  • my $hello = "Hello, ";
    — ASCII-строка.
  • my $hello = "½Hola, ";
    — строка Latin-1 без явного кодирования.
  • my $hello = "Kuirabá, ";
    — Unicode при включенном utf8 или encoding.

Если обе строки Unicode, их конкатенация будет корректна. Если же обе октетные последовательности (например Latin-1), результат тоже будет верным. Однако смешивание кодировок (например UTF-8 и Latin-1) приведёт к ошибкам.

my $binary = 0b101010;
my $octal = 052;
my $hex = 0x20;

Префиксы 0b, 0 (для восьмиричных) и 0x указывают систему счисления. Внимание: ноль перед числом всегда означает восьмеричное представление.

Числа

my $integer = 42;
my $float = 0.007;
my $sci_float = 1.02e14;
my $binary = 0b101010;
my $octal = 052;
my $hex = 0x20;
# (Perl ≥5.22)
my $hex_float = 0x1.0p-3;

Внутреннее представление чисел может привести к неточностям (например, 1.99 + 1.99 ≠ 4). Используйте Math::BigInt для больших значений.

Undef и пустые списки

say defined $status;  # → 1
say defined undef;   # → пустая строка

Конструкция continue

Блок continue выполняется перед каждой итерацией, даже после next:

    next unless $i % 2;
    say $i;
}
continue {
    say 'Continuing...';
    $i++;
}

Скаляры (Scalars)

Фундаментальный тип данных Perl — скаляр ($):

  • Может содержать строки, числа, файловые дескрипторы или ссылки.
  • Поддерживает явное преобразование типов:
    • my $value;
$value = 123.456;   # число
$value = "test";     # строка
$value = undef;      # неопределенное значение

Контекст определяет поведение операций:

my $zip_code = 97123;
my $city_state_zip = 'Hillsboro, Oregon' . ' ' . $zip_code; # строковый контекст

Преобразование строк к числам:

my $call_sign = 'KBMIU';
my $next_sign = ++$call_sign; # инкремент строки (работает для алфавитных последовательностей)

Важно:

Избегайте резких переходов типов в скалярах, чтобы не запутать читателей кода.

Магия одностороннего увеличения

Это магическое поведение при увеличении строки не имеет обратного действия. Нельзя восстановить прежнее строковое значение выражением $call_sign--.

Операция увеличения строки превращает a в b и z в aa, с учётом регистра и набора символов. Например, ZZ9 становится AAA0, а ZZ09 — ZZ10. Цифры переполняются, как на одометре машины.

Ссылки в строковом и числовом контекстах

Оценка ссылки в строковом контексте даёт строку. В числовом контексте — число. Ни одно из этих действий не модифицирует саму ссылку, и восстановить её из результата невозможно:


my $authors = [qw( Pratchett Vinge Conway )];
my $stringy_ref = '' . $authors;
my $numeric_ref = 0 + $authors;

$authors всё ещё остаётся ссылкой, но $stringy_ref — это просто строка без связи с исходной ссылкой, а $numeric_ref — число, также не связанное с ней.

Структура скаляров

Чтобы допускать преобразование без потери данных, скаляры Perl могут содержать одновременно числовое и строковое представление. Внутренняя структура скаляра содержит два слота: числовой и строковый. Доступ к строке в числовом контексте создаёт скаляр с обоими значениями.

Скаляры не имеют отдельного слота для булевых значений. В булевом контексте пустая строка ('') и строка '0' считаются ложными. Все остальные строки — истинными. Числа 0, 0.0 и 0e0 — ложны. Остальные числа — истинны.

Что есть истина?

Будьте внимательны: строки '0.0' и '0e0' считаются истинными. Это пример различия между тем, что выглядит как число, и тем, что им является. undef всегда считается ложным значением.

Массивы

Массив — агрегатный тип данных в Perl, способный хранить ноль или более скаляров. Элементы массива доступны по индексам и могут быть добавлены или удалены в любое время. Размер массива изменяется динамически.

Символ @ обозначает массив. Объявление массива:


my @items;

Элементы массива

Для доступа к элементу массива используется символ $. $cats[0] однозначно указывает на первый элемент массива @cats.


# @cats содержит список объектов Cat
my $first_cat = $cats[0];

Последний индекс массива зависит от количества элементов. В скалярном контексте (например, при присваивании, конкатенации, сложении или в булевом выражении) массив возвращает число элементов:


# скалярное присваивание
my $num_cats = @cats;

# конкатенация строк
say 'У меня ' . @cats . ' кошек!';

# сложение
my $num_animals = @cats + @dogs + @fish;

# булев контекст
say 'Да, я кошатник!' if @cats;

Для получения индекса последнего элемента массива можно вычесть 1 из общего количества или использовать синтаксис $#cats:


my $first_index = 0;
my $last_index = @cats - 1;
# или
# my $last_index = $#cats;
say "У первого кота индекс $first_index, а у последнего — $last_index.";

Часто важна не абсолютная, а относительная позиция элемента массива. Чтобы обратиться к элементам с конца массива, используйте отрицательные индексы: -1 — это последний элемент, -2 — предпоследний и т. д.

my $last_cat = $cats[-1];
my $second_to_last_cat = $cats[-2];

Оператор $# можно использовать для изменения размера массива "на месте":

Переменные массивов в Perl изменяемые: при уменьшении — обрезаются лишние элементы, при расширении — недостающие позиции заполняются undef.

Присваивание массивам

Присваивать значения можно напрямую по индексу:

my @cats;
$cats[3] = 'Jack';
$cats[2] = 'Tuxedo';
$cats[0] = 'Daisy';
$cats[1] = 'Petunia';
$cats[4] = 'Brad';
$cats[5] = 'Choco';

Если указать индекс за пределами текущего массива — Perl сам расширит массив и заполнит промежуточные элементы undef.

Сокращённая форма инициализации массива:

my @cats = ( 'Daisy', 'Petunia', 'Tuxedo', ... );

Важно: скобки действительно создают список. Без них — будет назначено только первое значение, остальные — проигнорированы.

Можно присваивать массивам любые выражения, возвращающие список:

my @cats = get_cat_list();
my @timeinfo = localtime();
my @nums = 1 .. 10;

Присваивание скалярному элементу массива навязывает скалярный контекст, а присваивание массиву — списковый.

Для очистки массива присвойте ему пустой список:

@dates = ();

Это редкий случай, когда скобки действительно указывают на список, и без них код был бы неясен.

Операции с массивами

Иногда удобнее использовать массив как упорядоченную изменяемую коллекцию. Perl предлагает несколько операций для работы с элементами.

push и pop добавляют и удаляют элементы с конца массива:

my @meals;
push @meals, qw( hamburgers pizza lasagna turnip );
pop @meals;

push возвращает новое количество элементов, pop — удалённый элемент.

Можно легко объединить несколько массивов:

push @meals, @breakfast, @lunch, @dinner;

unshift и shift работают с началом массива — добавляют и удаляют элементы соответственно:

unshift @meals, qw( tofu spanakopita taquitos );
shift @meals;

Возвращаемые значения unshift и shift редко используются.

splice позволяет удалять и заменять элементы массива, начиная с заданной позиции и количества:

my ($winner, $runnerup) = splice @finalists, 0, 2;
# или
my $winner = shift @finalists;
my $runnerup = shift @finalists;

each позволяет перебирать массив по индексам и значениям...

Срезы массивов (Array Slices)

my @youngest_cats = @cats[-1, -2];
my @oldest_cats = @cats[0 .. 2];

Срезы массивов позволяют выбрать несколько элементов через их индексы. Например:

  • @cats[-1, -2]: последние два кота.
  • @cats[0..2]: первые три элемента (индексы 0-2).
@users[@replace_indices] = @replace_users;

Обратите внимание: срез массива требует списочного контекста. Использование скалярного контекста вызовет предупреждение:

Scalar value @cats[1] better written as $cats[1]...

Массивы и контекст (Arrays and Context)

take_pets_to_vet( @cats, @dogs );
sub take_pets_to_vet {
    my (@cats, @dogs) = @_;
}

В этом примере массивы расплющиваются в один список. Функция получит все элементы как 9 отдельных переменных.

Интерполяция массивов (Array Interpolation)

say "Pets: @pets";

Массив интерполируется как строка, разделённая пробелами. Для изменения разделителя используйте глобальную переменную $" (по умолчанию — пробел):

${"Список: @pets". $LIST_SEPARATOR = " / ";

Важно:

  • Массивы в списке всегда расплющиваются.
  • Чтобы сохранить структуру, используйте ссылки на массивы (array references).
# ПЛОХО: создает плоский список
my @numbers = (1..10, (11..20), 21..30);

# ХОРОШО: массив ссылок на массивы
my $nested_arrays = [ [1..10], [11..20], [21..30] ];

В этом примере переменная $name содержит строку, которая также является ключом хэша. Как и при доступе к отдельному элементу массива, сигил изменяется с % на $ для обозначения обращения к скалярному значению по ключу.

my $address = $addresses{$name};

Вы можете использовать строковые литералы в качестве ключей хэша. Perl автоматически заключает в кавычки bareword-значения по тем же правилам, что и при использовании «толстых» запятых:

# автоматически заключено в кавычки
my $address = $addresses{Victor};
# требует кавычек — невалидный bareword
my $address = $addresses{'Sue-Linn'};
# вызов функции требует уточнения
my $address = $addresses{get_name()};

Не цитируйте меня

Новички часто всегда заключают строковые ключи в кавычки, но опытные разработчики избегают этого, когда можно. Тогда наличие кавычек может указывать на то, что вы делаете что-то необычное намеренно.

Даже встроенные функции Perl подвержены автокавычкам:

my %addresses = (
    Leonardo => '1123 Fib Place',
    Utako => 'Cantor Hotel, Room 1',
    sub get_address_from_name {
        return $addresses{+shift};
    }
);

Унарный плюс превращает то, что иначе было бы bareword-значением (shift), в выражение. Это значит, что вы можете использовать любое выражение — не только вызов функции — в качестве ключа хэша:

# так делать не стоит, но можно
my $address = $addresses{reverse 'odranoeL'};
# интерполяция работает
my $address = $addresses{"$first_name $last_name"};
# также работают вызовы методов
my $address = $addresses{ $user->name };

Ключи хэша могут быть только строками. Всё, что приводится к строке, допустимо. Perl даже приводит выражения к строке, если это необходимо. Например, если использовать объект в качестве ключа хэша, Perl сохранит его строковое представление:

for my $isbn (@isbns) {
    my $book = Book->fetch_by_isbn($isbn);
    # скорее всего, не то что вы хотите
    $books{$book} = $book->price;
}

Такой ключ будет выглядеть как Book=HASH(0x222d148). Book — имя класса, HASH указывает на то, что это объект, а 0x222d148 — адрес структуры данных в памяти.

Проверка существования ключа

Оператор exists возвращает логическое значение, показывающее, содержится ли ключ в хэше:

my %addresses = (
    Leonardo => '1123 Fib Place',
    Utako => 'Cantor Hotel, Room 1',
);
say "Есть адрес Леонардо" if exists $addresses{Leonardo};
say "Есть адрес Уорни" if exists $addresses{Warnie};

Использование exists вместо прямого доступа к значению по ключу позволяет избежать двух проблем. Во-первых, это не проверяет значение на истинность — ключ может существовать, даже если его значение ложно (включая undef):

my %false_key_value = ( 0 => '' );
ok %false_key_value, 'хэш с ложным ключом и значением должен быть true';

Во-вторых, exists предотвращает автосоздание вложенных структур (автовивификацию):

$addresses{Leibniz} = undef;
say "Готфрид живёт по адресу $addresses{Leibniz}"
    if exists $addresses{Leibniz}
    && defined $addresses{Leibniz};

Доступ к ключам и значениям хэша

Хэши — агрегатные переменные, но их парная структура уникальна. Perl позволяет итерироваться по ключам, значениям или парам ключ/значение.

Оператор keys возвращает список ключей:

for my $addressee (keys %addresses) {
    say "Найден адрес для $addressee!";
}

Оператор values — список значений:

for my $address (values %addresses) {
    say "Кто-то живёт по адресу $address";
}

Оператор each возвращает пары ключ/значение:

while (my ($addressee, $address) = each %addresses) {
    say "$addressee живёт по адресу $address";
}

В отличие от массивов, порядок элементов хэша не гарантируется — он зависит от реализации Perl, размера хэша и случайного фактора. Однако, порядок согласован между keys, values и each. Изменение хэша может повлиять на порядок.

Порядок обхода можно использовать, если хеш остаётся неизменным. Однако даже при совпадении ключей и значений у двух хешей нельзя полагаться на одинаковый порядок обхода: они могли быть сконструированы по-разному или изменены (удаление элементов и т.п.). Начиная с Perl 5.18, даже при одинаковой сборке хешей порядок обхода между ними может отличаться.

Перечитайте предыдущий абзац ещё раз. Это действительно важно.

У каждого хеша есть только один итератор для оператора each. Нельзя безопасно перебирать один и тот же хеш с помощью each одновременно в двух местах: если начнётся новый проход, старый завершится преждевременно, а новый начнётся с середины.

Старайтесь не вызывать функции, которые могут сами начать обход хеша через each. Это редко становится проблемой, но отладка будет неприятной. Сбросить итератор можно, вызвав keys или values без использования результата:

# сброс итератора хеша
    keys %addresses;
    while (my ($addressee, $address) = each %addresses) {
        ...
    }

Срезы хеша

Срез хеша — это список элементов, извлечённых по нескольким ключам за одну операцию. Например, чтобы инициализировать несколько элементов сразу:

my %cats;
    @cats{qw( Jack Brad Mars Grumpy )} = (1) x 4;

Это эквивалентно следующей записи:

my %cats = map { $_ => 1 } qw( Jack Brad Mars Grumpy );

Обрати внимание: присваивание через срез может как перезаписывать, так и дополнять существующий хеш.

Срезы позволяют за один раз извлечь несколько значений из хеша. Как и в случае с массивами, символ меняется на @ для указания работы в списочном контексте. Фигурные скобки указывают, что идёт доступ к хешу:

my @buyer_addresses = @addresses{ @buyers };

Срезы удобны для объединения хешей:

my %addresses = ( ... );
    my %canada_addresses = ( ... );
    @addresses{ keys %canada_addresses } = values %canada_addresses;

Это аналогично ручному перебору содержимого %canada_addresses, но гораздо короче.

Важно: здесь порядок ключей и значений должен совпадать. Perl гарантирует это, но только если между операциями keys и values хеш не изменяется.

Что если один и тот же ключ есть в обоих хешах? Тогда срез всегда перезапишет значение в %addresses. Если нужно другое поведение, стоит использовать обычный цикл.

Пустой хеш

Пустой хеш не содержит ни ключей, ни значений. В булевом контексте он оценивается как ложь. Хеш, содержащий хотя бы одну пару ключ/значение, оценивается как истина, даже если сами ключи или значения (или и то, и другое) в булевом контексте являются ложными.


    use Test::More;
    my %empty;
    ok ! %empty, 'empty hash should evaluate false';
    my %false_key = ( 0 => 'true value' );
    ok %false_key, 'hash containing false key should evaluate to true';
    my %false_value = ( 'true key' => 0 );
    ok %false_value, 'hash containing false value should evaluate to true';
    done_testing();

В скалярном контексте хеш оценивается как строка, представляющая собой внутренние детали реализации (например, отношение заполненных бакетов), которые можно игнорировать. В булевом скалярном контексте эта строка интерпретируется как ложь.

В списковом контексте хеш разворачивается в список пар ключ/значение, аналогичный тому, что выдаёт оператор each. Но итерироваться по такому списку через while нельзя: это приведёт к бесконечному циклу:


    # бесконечный цикл для непустого хеша
    while (my ($key, $value) = %hash) {
        ...
    }

Итерироваться по списку ключей и значений можно через for, но тогда переменная будет принимать поочерёдно ключ, затем значение, потому что Perl "сплющит" хеш в один список.

Идиомы работы с хешами

Поскольку каждый ключ в хеше существует только один раз, при многократном присваивании одного и того же ключа сохраняется последнее значение. Это удобно, например, для поиска уникальных элементов списка:


    my %uniq;
    undef @uniq{ @items };
    my @uniques = keys %uniq;

Использование undef на срезе хеша устанавливает значения в undef. Это самый дешёвый способ выполнять операции над множествами.

Хеши также полезны для подсчёта элементов, например, IP-адресов в логах:


    my %ip_addresses;
    while (my $line = <$logfile>) {
        chomp $line;
        my ($ip, $resource) = analyze_line( $line );
        $ip_addresses{$ip}++;
        ...
    }

Начальное значение для элемента хеша — undef. Оператор ++ рассматривает его как ноль. Таким образом, если значение отсутствует, оно создаётся (как undef) и сразу увеличивается до одного.

Эта стратегия также подходит для кэширования дорогостоящих операций:


    {
        my %user_cache;
        sub fetch_user {
            my $id = shift;
            $user_cache{$id} //= create_user($id);
            return $user_cache{$id};
        }
    }

Этот "оркский манёвр" (or-cache) возвращает значение из хеша, если оно есть, иначе вычисляет его, сохраняет и возвращает. Оператор //= присваивает значение правому операнду только если левый операнд неопределён.

Ранее для этой задачи использовали оператор ||=, но //= предпочтительнее, так как проверяет определённость, а не истинность значения.

Если функция принимает несколько аргументов, используйте "проглатывающий" хеш (Slurping, стр. 109), чтобы собрать пары ключ/значение в один хеш в качестве именованных аргументов функции:

sub make_sundae {
        my %parameters = @_;
        ...
    }
    
    make_sundae(
        flavor  => 'Lemon Burst',
        topping => 'cookie bits'
    );

Такой подход позволяет установить значения по умолчанию:

sub make_sundae {
        my %parameters = @_;
        $parameters{flavor}    //= 'Vanilla';
        $parameters{topping}   //= 'fudge';
        $parameters{sprinkles} //= 100;
        ...
    }

Или сразу задать их при инициализации хеша — поздние присваивания имеют приоритет над ранними:

sub make_sundae {
        my %parameters = (
            flavor    => 'Vanilla',
            topping   => 'fudge',
            sprinkles => 100,
            @_,
        );
        ...
    }

Блокировка хешей

Так как ключи хеша — это "голые слова", они плохо защищены от опечаток по сравнению с именами функций и переменных при использовании `strict`. Слабоизвестный модуль ядра Hash::Util помогает сделать хеши безопаснее.

Чтобы предотвратить случайное добавление лишнего ключа (через опечатку или недоверенный ввод), используйте функцию lock_keys(), чтобы ограничить хеш его текущими ключами. Любая попытка добавить новый ключ вызовет исключение. Аналогично можно заблокировать или разблокировать конкретное значение ключа (lock_value() и unlock_value()) и сделать весь хеш только для чтения или снова доступным для записи (lock_hash() и unlock_hash()).

Это не строгая безопасность — любой может обойти её с помощью разблокировки, но она хорошо защищает от опечаток и случайных ошибок.

Приведение типов

В течение жизни переменной Perl может содержать значения разных типов — строки, числа, рациональные числа и так далее. Вместо жесткой типизации Perl полагается на контекст операторов (числовой, строковый и булевый контексты, стр. 7), чтобы определить, как обрабатывать значения. По замыслу Perl старается "делать то, что вы имели в виду" — это называют DWIM (Do What I Mean), но при этом требуется точность намерений. Если вы обращаетесь к значению как к строке, Perl постарается привести его к строке.

Булево приведение

Булево приведение происходит, когда вы проверяете значение на истинность, например, в условиях if или while. Числовой ноль, undef, пустая строка и строка '0' считаются ложными. Все остальные значения — включая строки вроде '0.0', '0e' и '0 but true' — считаются истинными.

Когда скаляр имеет и строковую, и числовую части (Dualvars, стр. 75), Perl предпочитает проверять строковую часть для булевой проверки. Строка '0 but true' численно равна нулю, но не является пустой строкой, поэтому считается истинной в булевом контексте.

Приведение типов в строки

Приведение к строке происходит при использовании строковых операторов, таких как сравнения (eq и cmp), конкатенация, split, substr и регулярные выражения, а также при использовании значения или выражения в качестве ключа хеша. Неопределённое значение превращается в пустую строку, но вызывает предупреждение "использование неинициализированного значения". Числа приводятся к строкам, содержащим их значения: например, число 10 превращается в строку "10". Можно даже разбить число на отдельные цифры:

my @digits = split '', 1234567890;

Приведение к числам

Приведение к числу происходит при использовании числовых операторов сравнения (таких как == и <=>), при выполнении математических операций и при использовании значения или выражения в качестве индекса массива или списка. Неопределённое значение приводится к нулю и вызывает предупреждение "использование неинициализированного значения". Строки, не начинающиеся с числа, приводятся к нулю и вызывают предупреждение "аргумент не является числом". Строки, начинающиеся с допустимых для чисел символов, превращаются в соответствующие значения без предупреждений. Например:

  • "10 leptons leaping" превращается в 10
  • "6.022e23 moles marauding" превращается в 6.022e23

Модуль ядра Scalar::Util содержит функцию looks_like_number(), которая использует те же правила, что и парсер Perl, для извлечения числа из строки.

Радость математиков

Строки Inf и Infinity представляют бесконечность и ведут себя как числа. Строка NaN представляет "не число". Их приведение не вызывает предупреждений о некорректных числах. Однако имейте в виду, что представление бесконечности и NaN может различаться на разных платформах; Perl обеспечивает внутреннюю согласованность, даже если платформа — нет.

Приведение ссылок

При попытке разыменования не-ссылки Perl автоматически превращает значение в ссылку. Этот процесс называется автоживлением и полезен при работе с вложенными структурами данных:

my %users;
    $users{Brad}{id} = 228;
    $users{Jack}{id} = 229;

Хотя изначально хеш не содержал записей для Brad и Jack, Perl автоматически создал ссылки на вложенные хеши и присвоил им пары ключ/значение.

Кэшированное приведение

Внутреннее представление значения в Perl хранит одновременно строковую и числовую форму. Приведение числа к строке не уничтожает числовое значение, а лишь добавляет строковую версию. Аналогично, приведение строки к числу добавляет числовую часть, не затрагивая строковую.

Некоторые операции Perl предпочитают одну форму над другой — например, булевы проверки используют строковое представление. Кэшированное приведение редко приводит к неожиданностям, но знание об этом может помочь в диагностике странных ситуаций.

Двойные переменные (Dualvars)

Доступ к двойной природе значений Perl можно получить через модуль Scalar::Util и функцию dualvar(), которая позволяет отдельно управлять строковой и числовой частью значения:

use Scalar::Util 'dualvar';
    my $false_name = dualvar 0, 'Sparkles & Blue';
    say 'Булево истинно!' if !! $false_name;
    say 'Числовое ложно!' unless 0 + $false_name;
    say 'Строковое истинно!' if '' . $false_name;

Пакеты
Пространство имён в Perl ассоциирует и инкапсулирует различные именованные сущности. Это похоже на вашу фамилию или название бренда. В отличие от реального мира, пространство имён не подразумевает наличие прямой связи между сущностями — такие связи могут быть, но это не обязательно.

Пакет в Perl — это набор кода в одном пространстве имён. Различие тонкое: пакет представляет исходный код, а пространство имён — внутреннюю структуру данных Perl для его группировки.

Встроенная функция package объявляет пакет и пространство имён: 

package MyCode;
our @boxes;
sub add_box { ... }

Все глобальные переменные и функции, объявленные или использованные после package, относятся к символам в пространстве имён MyCode. Чтобы обратиться к переменной @boxes из пространства имён main, нужно использовать полное имя @MyCode::boxes. Полное имя включает имя пакета, поэтому функцию add_box() можно вызвать через MyCode::add_box().

Область действия пакета продолжается до следующего объявления package или до конца файла. Также можно ограничить область блока, используя фигурные скобки: 

package Pinball::Wizard {
our $VERSION = 1969;
}

Пакет по умолчанию — это пакет main. Без явного объявления пакета, весь код находится в main. Это правило применяется к однострочным командам, отдельным программам и даже к модулям (.pm файлам).

Помимо имени, пакет имеет версию и три неявных метода: import() (см. "Импортирование"), unimport() и VERSION(). Метод VERSION() возвращает значение переменной $VERSION в пакете. По соглашению, версия состоит из целых чисел, разделённых точками, например 1.23 или 1.1.10.

Perl поддерживает более строгий формат версий, описанный в perldoc version::Internals, где версия должна начинаться с символа v и содержать как минимум три числа: 

package MyCode v1.2.1;

В сочетании с блочной формой записи можно написать: 

package Pinball::Wizard v1969.3.7 { ... }

Чаще встречается более старый стиль: 

package MyCode;
our $VERSION = 1.21;

Каждый пакет наследует метод VERSION() от базового класса UNIVERSAL. Этот метод возвращает значение $VERSION: 

my $version = Some::Plugin->VERSION;

Если передать аргумент, метод VERSION() выбросит исключение, если версия модуля меньше указанной: 

# требуется версия не ниже 2.1
Some::Plugin->VERSION(2.1);
die "Your plugin $version is too old" unless $version > 2;

Вы можете переопределить VERSION(), но для этого редко бывают веские причины.

Пакеты и пространства имён

Каждая директива package создаёт новое пространство имён, если это необходимо. После разбора директивы Perl сохраняет все последующие глобальные символы пакета (глобальные переменные и функции) в этом пространстве.

В Perl пространства имён открытые. Вы можете добавлять функции или переменные в пространство имён в любой момент — либо через новую директиву package:

package Pack {
    sub first_sub { ... }
}
Pack::first_sub();
package Pack {
    sub second_sub { ... }
}
Pack::second_sub();

...или с помощью полностью квалифицированных имён функций:

# неявно
package main;
sub Pack::third_sub { ... }

Вы можете добавлять код в пакет в любой момент компиляции или выполнения программы, независимо от файла. Однако построение пакета из нескольких объявлений в разных файлах может затруднить понимание кода.

Пространства имён могут иметь сколько угодно уровней в зависимости от вашей структуры, но они не являются иерархическими. Единственная связь между пакетами — семантическая, а не техническая.

Многие проекты создают свои собственные пространства имён верхнего уровня, чтобы избежать глобальных конфликтов и организовать код на диске. Например:

  • StrangeMonkey — имя проекта
  • StrangeMonkey::UI — код пользовательского интерфейса
  • StrangeMonkey::Persistence — код для работы с данными
  • StrangeMonkey::Test — код для тестирования проекта

Это лишь соглашение, но весьма полезное.

Ссылки

Perl обычно ведёт себя так, как вы ожидаете, даже если это поведение тонкое. Рассмотрим передачу значений в функции:

sub reverse_greeting {
    my $name = reverse shift;
    return "Hello, $name!";
}
my $name = 'Chuck';
say reverse_greeting( $name );
say $name;

Вне функции переменная $name по-прежнему содержит Chuck, хотя переданное внутрь функции значение переворачивается в kcuhC. Это ожидаемо: значение $name снаружи функции и внутри — разные.

Иначе вам пришлось бы вручную копировать каждое значение перед его изменением, что привело бы к излишней защите кода.

Иногда полезно изменять значения на месте. Например, если вы хотите передать хэш в функцию для изменения, создание и возврат нового хэша каждый раз было бы утомительным и неэффективным (если только компилятор не обладает чудесной оптимизацией).

Perl предлагает механизм ссылок, которые позволяют изменять оригинальное значение без создания копии. Все ссылки на это значение будут видеть обновлённые данные. Ссылка в Perl — это полноценная скалярная переменная, которая указывает на другую полноценную переменную.

Ссылки на скаляры

Оператор ссылки — обратный слэш (\). В скалярном контексте он создаёт одну ссылку на значение. В списочном контексте — список ссылок. Чтобы создать ссылку на переменную $name:


my $name = 'Larry';
my $name_ref = \$name;

Чтобы получить значение, на которое указывает ссылка, нужно разыменовать её, добавив дополнительный сигил для каждого уровня разыменования:


sub reverse_in_place {
    my $name_ref = shift;
    $$name_ref = reverse $$name_ref;
}

my $name = 'Blabby';
reverse_in_place( \$name );
say $name;

Двойной знак доллара $$ разыменовывает скалярную ссылку.

Параметры в массиве @_ ведут себя как псевдонимы переменных вызывающего кода, так что можно изменять их на месте:


sub reverse_value_in_place {
    $_[0] = reverse $_[0];
}

my $name = 'allizocohC';
reverse_value_in_place( $name );
say $name;

Обычно не стоит так делать — вызывающий код редко ожидает изменения своих аргументов. Чтобы избежать такого поведения, присваивайте параметры локальным переменным внутри функций — это создаёт их копии.

Экономия памяти при помощи ссылок

Изменение значений на месте или возврат ссылки на скаляр может сэкономить память. Поскольку Perl копирует значения при присваивании, могут появляться множественные копии одной и той же строки. Работа со ссылками приводит лишь к копированию самих ссылок — это гораздо дешевле. Однако перед изменением кода для работы только с ссылками стоит замерить, будет ли это иметь реальное значение.

Сложные ссылки могут требовать использования фигурных скобок для уточнения частей выражения. Эта запись всегда допустима и иногда повышает читаемость, а иногда — наоборот:


sub reverse_in_place {
    my $name_ref = shift;
    ${ $name_ref } = reverse ${ $name_ref };
}

Если забыть разыменовать скалярную ссылку, Perl, скорее всего, преобразует её в строку вида SCALAR(0x93339e8) или в числовое значение 0x93339e8. Это указывает на тип ссылки и её адрес в памяти (но напрямую с этим адресом ничего сделать нельзя).

Ссылки — это не указатели

Perl не даёт прямого доступа к памяти. Адрес ссылки — это лишь идентификатор. В отличие от указателей в C, нельзя изменить адрес ссылки или использовать его как настоящий адрес в памяти. Хотя адреса ссылок обычно уникальны, Perl может переиспользовать области памяти после освобождения ресурсов.

Ссылки на массивы полезны в нескольких случаях:

  • Для передачи и возврата массивов из функций без их расплющивания в список
  • Для создания многомерных структур данных
  • Чтобы избежать лишнего копирования массивов
  • Для хранения анонимных структур данных

Используйте оператор ссылки для создания ссылки на объявленный массив:

my @cards = qw( K Q J 10 9 8 7 6 5 4 3 2 A );
my $cards_ref = \@cards;

Любые изменения через $cards_ref изменяют @cards и наоборот.

Доступ ко всему массиву с помощью символа @:

my $card_count = @$cards_ref;
my @card_copy = @$cards_ref;

Доступ к отдельным элементам через оператор ->:

my $first_card = $cards_ref->[0];
my $last_card = $cards_ref->[-1];

Альтернативный (но менее читаемый) способ:

my $first_card = $$cards_ref[0];

Для извлечения среза массива через ссылку используйте фигурные скобки:

my @high_cards = @{ $cards_ref }[0 .. 2, -1];

Создание анонимного массива:

my $suits_ref = [qw( Monkeys Robots Dinos Cheese )];

Пример отличия обычной и анонимной ссылки на массив:

my @meals = qw( soup sandwiches pizza );
my $sunday_ref = \@meals;
my $monday_ref = \@meals;
push @meals, 'ice cream sundae';

Обе ссылки увидят изменения. А при использовании анонимных массивов:

my @meals = qw( soup sandwiches pizza );
my $sunday_ref = [ @meals ];
my $monday_ref = [ @meals ];
push @meals, 'berry pie';

Ссылки останутся неизменными.

Ссылки на хэши

Создание ссылки на хэш:

my %colors = (
    blue => 'azul',
    gold => 'dorado',
    red => 'rojo',
    yellow => 'amarillo',
    purple => 'morado',
);
my $colors_ref = \%colors;

Доступ к ключам и значениям:

my @english_colors = keys %$colors_ref;
my @spanish_colors = values %$colors_ref;

Доступ к отдельным значениям:

sub translate_to_spanish {
    my $color = shift;
    return $colors_ref->{$color};
    # или return $$colors_ref{$color};
}

Извлечение среза из хэша по ссылке:

my @colors = qw( red blue green );
my @colores = @{ $colors_ref }{@colors};

Создание анонимного хэша:

my $food_ref = {
    'birthday cake' => 'la torta de cumpleaños',
    candy => 'dulces',
    cupcake => 'bizcochito',
    'ice cream' => 'helado',
};

Внимание! Новички часто путают анонимные хэши и обычные. Для обычного хэша используйте круглые скобки (), для анонимного — фигурные {}.

Ссылки на функции

Perl поддерживает функции как полноценные значения, подобно массивам и хэшам. Это означает поддержку ссылок на функции, что позволяет использовать продвинутые техники (например, замыкания).

Создание ссылки на именованную функцию:

sub bake_cake { say 'Baking a wonderful cake!' };
my $cake_ref = \&bake_cake;

Без знака & будет взята ссылка на возвращаемое значение функции, а не на саму функцию.

Создание анонимной функции:

my $pie_ref = sub { say 'Making a delicious pie!' };

Анонимная функция компилируется, но не регистрируется в пространстве имён. Доступ возможен только через ссылку.

Вызов ссылки на функцию через оператор стрелки:

$cake_ref->();
$pie_ref->();

Вызов в стиле Perl 4

Можно вызывать функцию через & вместо стрелки, например &$cupcake_ref(), но так делать не рекомендуется из-за особенностей разбора аргументов.

Передача аргументов в функцию через скобки:

$bake_something_ref->( 'cupcakes' );

Ссылки на функции можно использовать как методы для объектов:

my $clean = $robot_maid->can( 'cleanup' );
$robot_maid->$clean( $kitchen );

Ссылки на файловые дескрипторы

Лексические файловые дескрипторы (формы open и opendir) работают через ссылки. Они являются объектами класса IO::File и позволяют напрямую вызывать методы:

use autodie 'open';
open my $out_fh, '>', 'output_file.txt';
$out_fh->say( 'Have some text!' );

Старый код может использовать IO::Handle или ссылки на глобальные дескрипторы через typeglob:

local *FH;
open FH, "> $file" or die "Can't write '$file': $!";
my $fh = \*FH;

Современный подход — использовать лексические файловые дескрипторы, которые автоматически закрываются при выходе из области видимости.

Счётчики ссылок

Perl управляет памятью через подсчёт ссылок. Каждый раз при создании новой ссылки счётчик увеличивается, при уничтожении ссылки — уменьшается. Когда счётчик достигает нуля, значение освобождается.

Пример работы счётчика ссылок с файловым дескриптором в области видимости:

say 'file not open';
{
    open my $fh, '>', 'inner_scope.txt';
    $fh->say( 'file open here' );
}
say 'file closed here';

Когда блок завершается, переменная $fh уничтожается, файловый дескриптор автоматически закрывается.

Важно: Нужно понимать, что работа с ссылками напрямую влияет на управление памятью Perl (особенно при изучении циклических ссылок).

Ссылки и функции

Если вы передаёте ссылки в качестве аргументов функций, тщательно документируйте свои намерения. Модификация содержимого ссылки внутри функции может неожиданно изменить данные вызывающего кода.

Чтобы изменить данные, но не саму ссылку, сделайте копию:

my @new_array = @{ $array_ref };
my %new_hash = %{ $hash_ref };

Это нужно не всегда, но явное клонирование помогает избежать неожиданных эффектов. Для вложенных структур можно использовать модуль Storable и его функцию dclone для глубокого копирования.

Постфиксная разыменовка

Начиная с Perl 5.20 (стабилизировано в 5.24), введена постфиксная разыменовка. Она позволяет читать выражение слева направо, без префиксов или фигурных скобок.

Пример для массива, используя символ массива @*:

my $recipients = [qw(
    Mother
    Father
    Partner
    Nephew
    Niece
    Neighbor
)];
for my $recipient ($recipients->@*) {
    say "Need to find a gift for $recipient";
}

Это особенно полезно для сложных структур данных:

my %recipients = (
    mandatory => [qw(Partner Nephew Niece)],
    optional => [qw(Mother Father)],
    mmmmmmmaybe => [qw(Neighbor)],
);
for my $recipient ($recipients{optional}->@*) {
    say "Probably should find a gift for $recipient";
}

Или при работе с результатами функций/методов:

say "Have \$200 to spend on " . join ', ',
    get_recipients_for_budget({ usd => 200 })->@*;

Для хэшей используется аналогичная нотация с символом %*:

my $holiday_starts = {
    Hannukah => '2020-12-10',
    Christmas => '2020-12-25',
    Kwanzaa => '2020-12-26',
};
while (my ($holiday, $start_date) = each $holiday_starts->%*) {
    ...
}

Также можно разыменовывать значения, возвращаемые функциями:

while (my ($holiday, $start_date) = each holiday_start_dates_for(2020)->%*) {
    ...
}

Можно делать срезы массивов и хэшей:

my @pto_holidays = $holiday_starts->@{qw( Hannukah Kwanzaa )};
my @first_recipients = $recipients->@[0 .. 3];

Для скаляров применяется ->$*:

my $not_a_constant = \"variable";
say $not_a_constant->$*;

Постфиксная разыменовка не поддерживает срезы для скаляров.

Вы можете выбрать единообразный стиль: использовать только префиксную, обрамляющую или постфиксную разыменовку в своём коде.

Дополнительную информацию смотрите в разделе "Postfix Dereference Syntax" документации perlref.

Вложенные структуры данных

Агрегатные типы данных Perl — массивы и хэши — хранят скаляры по целочисленным или строковым ключам. Обратите внимание: именно скаляры.

Если попытаться вложить массив в массив напрямую, Perl расплющит все элементы в один массив:

my @counts = qw( eenie miney moe );
my @ducks = qw( huey dewey louie );
my @game = qw( duck duck grayduck );
my @famous_triplets = (
    @counts, @ducks, @game
);

Решение — использовать ссылки, которые позволяют создать массив массивов или хэш хэшей. Да, синтаксис ссылок выглядит чуть громоздко.

Создание ссылок на уже объявленные переменные:

my @famous_triplets = (
    \@counts, \@ducks, \@game
);

Или можно сразу использовать анонимные массивы:

my @famous_triplets = (
    [qw( eenie miney moe )],
    [qw( huey dewey louie )],
    [qw( duck duck goose )],
);

Создание хэша из анонимных хэшей:

my %meals = (
    breakfast => { entree => 'eggs', side => 'hash browns' },
    lunch => { entree => 'panini', side => 'apple' },
    dinner => { entree => 'steak', side => 'avocado salad' },
);

Запятая — не обязательна

Перл допускает запятую после последнего элемента списка. Это удобно для будущего добавления новых элементов.

Доступ к вложенным структурам

Используйте синтаксис ссылок для обращения к вложенным структурам. Символ переменной определяет, сколько данных нужно получить, а стрелка -> показывает, что часть данных — ссылка:

my $last_nephew = $famous_triplets[1]->[2];
my $meal_side = $meals{breakfast}->{side};

Стрелку можно опустить для массивов и хэшей (но не для функций):

my $nephew = $famous_triplets[1][2];
my $meal = $meals{breakfast}{side};
$actions{generous}{buy_food}->( $nephew, $meal );

Блоки для доступа к элементам

Используйте блоки для обращения к вложенным массивам или хэшам как к полноценным структурам:

my $nephew_count = @{ $famous_triplets[1] };
my $dinner_courses = keys %{ $meals{dinner} };

Или для среза вложенных данных:

my ($entree, $side) = @{ $meals{breakfast} }{ qw( entree side ) };

Для лучшей читаемости можно использовать временную переменную:

my $meal_ref = $meals{breakfast};
my ($entree, $side) = @$meal_ref{qw( entree side )};

Или использовать неявную подстановку цикла for (без my):

($entree, $side) = @{ $_ }{qw( entree side )} for $meals{breakfast};

Много примеров работы с вложенными структурами можно найти в справочнике perldoc perldsc ("Perl Data Structures Cookbook").

Автовивификация

Если попытаться записать значение в элемент глубоко вложенной структуры данных, Perl автоматически создаст весь путь к нужному месту:

my @aoaoaoa;
$aoaoaoa[0][0][0][0] = 'nested deeply';

После выполнения этого кода массив будет содержать вложенные друг в друга ссылки на массивы, где каждый уровень будет содержать один элемент.

Аналогично, если обратиться к неопределённому значению как к ссылке на хэш, Perl преобразует его в хэш-ссылку:

my %hohoh;
$hohoh{Robot}{Santa} = 'mostly harmful';

Такое поведение называется автовивификацией. Оно сокращает код инициализации, но не позволяет отличить намеренное создание новых элементов от случайной опечатки.

Автовивификация и строгий режим

Вы можете задаться вопросом: как использовать автовивификацию, включая строгие проверки (strict)? Всё зависит от проекта.

На стадии разработки допускайте свободу. На стадии тестирования и деплоя повышайте строгость, чтобы избежать побочных эффектов.

Пакет autovivification с CPAN позволяет локально отключить автовивификацию для определённых операций.

Можно явно проверять существование каждого уровня перед разыменованием, но это быстро приводит к громоздкому коду. Лучше пересмотреть модель данных, чтобы избежать чрезмерной вложенности.

Отладка вложенных структур данных

Из-за сложности синтаксиса разыменования и возможной путаницы с несколькими уровнями ссылок, отладка вложенных структур может быть сложной.

Модуль Data::Dumper из ядра Perl превращает произвольные структуры данных в строки кода Perl, помогая визуализировать содержимое:

use Data::Dumper;
my $complex_structure = {
    numbers => [ 1 .. 3 ],
    letters => [ 'a' .. 'c' ],
    objects => {
        breakfast => $continental,
        lunch => $late_tea,
        dinner => $banquet,
    },
};
print Dumper( $complex_structure );

Пример возможного вывода:

$VAR1 = {
    'numbers' => [1, 2, 3],
    'letters' => ['a', 'b', 'c'],
    'objects' => {
        'breakfast' => bless({...}, 'Breakfast'),
        'lunch' => bless({...}, 'Lunch'),
        'dinner' => bless({...}, 'Dinner'),
    },
};

Data::Dumper может выводить также объекты и ссылки на функции (если установить $Data::Dumper::Deparse в истинное значение).

Хотя Data::Dumper удобен, его вывод бывает громоздким. Для более читаемой отладки некоторые разработчики предпочитают модули YAML::XS или JSON (они не генерируют Perl-код, но дают более удобный для чтения результат).

Циклические ссылки

Механизм управления памятью Perl основан на подсчёте ссылок. Однако у него есть недостаток: две ссылки, указывающие друг на друга напрямую или косвенно, создают циклическую ссылку, которую Perl сам удалить не сможет.

Рассмотрим биологическую модель, где сущность имеет двух родителей и множество детей:

my $alice = { mother => '', father => '' };
my $robin = { mother => '', father => '' };
my $cianne = { mother => $alice, father => $robin };
push @{ $alice->{children} }, $cianne;
push @{ $robin->{children} }, $cianne;

Теперь $alice и $robin содержат ссылки на $cianne, а $cianne содержит ссылки обратно на $alice и $robin. Их счётчики ссылок никогда не станут равными нулю, и Perl не сможет освободить их память.

Решение: ручной разрыв или слабые ссылки

Можно вручную обнулить ссылки (например, очистить детей у родителей или родителей у ребёнка).

Или использовать слабые ссылки, которые не увеличивают счётчик ссылок. Для этого применяется функция weaken из модуля Scalar::Util:

use Scalar::Util 'weaken';

my $alice = { mother => '', father => '' };
my $robin = { mother => '', father => '' };
my $cianne = { mother => $alice, father => $robin };
push @{ $alice->{children} }, $cianne;
push @{ $robin->{children} }, $cianne;

weaken( $cianne->{mother} );
weaken( $cianne->{father} );

Теперь $cianne всё ещё "видит" $alice и $robin, но слабые ссылки не мешают сборщику мусора освободить объекты, когда их реальный счётчик ссылок станет нулевым.

Когда $alice будет уничтожена, ссылка $cianne->{mother} автоматически станет undef.

Большинство структур данных в Perl не требуют слабых ссылок, но когда они нужны — они незаменимы.

Альтернативы глубоко вложенным структурам

Хотя Perl легко справляется с глубоко вложенными структурами данных, человеческая сложность понимания таких структур высока.

Если у вас более двух-трёх уровней вложенности, задумайтесь о переходе к использованию классов и объектов (например, через Moose), чтобы сделать код более читаемым и поддерживаемым.
