Глава 10: Perl за пределами синтаксиса

Perl за пределами синтаксиса

«Простой» означает разное для разных программистов. Эффективные программисты понимают, как особенности Perl взаимодействуют и сочетаются. Их свободный код использует языковые шаблоны и идиомы. Результат такого «перлового мышления» — лаконичный, мощный и полезный код, который кажется простым, когда вы его понимаете.

Идиомы

У каждого языка есть общие шаблоны выражений — идиомы. Земля вращается вокруг своей оси, но мы говорим, что солнце встает или садится. Мы гордимся умными хаками, но морщимся от «грязных» решений и «плохо пахнущего» кода.

У Perl тоже есть свои идиомы: это и особенности языка, и приемы проектирования. Они придают вашему коду «перловый акцент». Их необязательно использовать, чтобы достичь результата, но они помогают раскрыть сильные стороны Perl.

Объект как $self

Объектная система Perl (например, Moose) воспринимает вызывающий объект метода как обычный параметр. Независимо от того, вызываете ли вы метод класса или экземпляра, первый элемент массива @_ всегда является вызывающим объектом. По соглашению, имя для инвоканта класса обычно $class, а для объекта — $self. Это соглашение настолько распространено, что полезные расширения вроде Moops предполагают использование $self.

Именованные параметры

Perl обожает списки. Списки — фундаментальная часть Perl. Благодаря «сплющиванию» и привязке списков вы можете соединять выражения, манипулируя данными любыми способами.

Хотя простота передачи аргументов в Perl (всё помещается в @_) иногда чрезмерна, присваивание значений из @_ в контексте списка позволяет распаковывать именованные параметры парами. Оператор «толстая запятая» превращает обычный список в понятные пары аргументов:

make_ice_cream_sundae(
    whipped_cream => 1,
    sprinkles => 1,
    banana => 0,
    ice_cream => 'mint chocolate chip',
);

Вы можете распаковать их в хеш и обращаться к нему как к одному аргументу:

sub make_ice_cream_sundae {
    my %args = @_;
    my $dessert = get_ice_cream($args{ice_cream});
    ...
}

Хеш или ссылка на хеш?

Книга Perl Best Practices рекомендует передавать ссылки на хеши. Это позволяет проводить валидацию на стороне вызывающего кода. Если вы передадите неправильное количество аргументов, ошибка произойдет в момент вызова.

Этот метод особенно удобен при написании import() и других функций:

sub import {
    my ($class, %args) = @_;
    my $calling_package = caller();
    ...
}

Преобразование Шварцциана

Трансформация Шварцциана — элегантная демонстрация распространенных в Perl операций над списками, заимствованных из Lisp.

Допустим, у вас есть хеш, связывающий имена сотрудников с их внутренними номерами:

my %extensions = (
    '000' => 'Damian',
    '002' => 'Wesley',
    '042' => 'Robin',
    '088' => 'Nic',
);

Правила кавычек ключей хеша: Жирная запятая работает только с barewords. Ключи с ведущим нулем воспринимаются как восьмеричные числа. Эту ошибку совершают все хотя бы раз.

Чтобы отсортировать список по именам, нужно отсортировать хеш по значениям:

my @sorted_names = sort values %extensions;

Но чтобы сохранить связь между именами и номерами, используется следующий прием:

my @pairs = map { [ $_, $extensions{$_} ] } keys %extensions;
my @sorted_pairs = sort { $a->[1] cmp $b->[1] } @pairs;

Оператор cmp сравнивает строки, а <=> — числа. Далее мы можем преобразовать результат:

my @formatted_exts = map { "$_->[1], ext. $_->[0]" } @sorted_pairs;
say for @formatted_exts;

Полная цепочка выглядит так:

say for
    map { "$_->[1], ext. $_->[0]" }
    sort { $a->[1] cmp $b->[1] }
    map { [ $_ => $extensions{$_} ] }
    keys %extensions;

Удобное считывание файлов

Магические переменные Perl можно контролировать через local. Пример считывания файла в одну строку:

my $file = do { local $/; <$fh> };

Или более экономично по памяти:

my $file;
{ local $/; $file = <$fh>; }

Модуль File::Slurper из CPAN является удобной и быстрой альтернативой.

Обработка main()

Хорошая практика — обернуть основную логику программы в функцию main(), чтобы избежать неожиданной инициализации переменных.

#!/usr/bin/perl
use Modern::Perl;
exit main(@ARGV);

sub main {
    ...
    return 0;
}
sub other_functions { ... }

Управляемое выполнение

Программа и модуль отличаются только намерением использования. Модуль можно сделать исполняемым, добавив проверку:

main() unless caller(0);

Если у модуля нет вызывающего кода, значит его запустили напрямую как программу (через perl path/to/Module.pm вместо use Module;).

Улучшенная проверка caller

Восьмой элемент списка, возвращаемого функцией caller в списковом контексте, будет истинным значением, если кадр стека соответствует вызову use или require, и undef в противном случае. Хотя это более точная информация, ею пользуются немногие.

Постфиксная валидация параметров

На CPAN есть модули для проверки параметров функций: Params::Validate и MooseX::Params::Validate — хорошие варианты. Однако простую проверку можно реализовать вручную.

Допустим, функция принимает ровно два аргумента:

use Carp 'croak';

sub groom_monkeys {
    if (@_ != 2) {
        croak 'Можно ухаживать только за двумя обезьянами!';
    }
    ...
}

Но с точки зрения читабельности важнее сначала выразить последствия, а не саму проверку:

croak 'Можно ухаживать только за двумя обезьянами!' unless @_ == 2;

Такой ранний выход с использованием постфиксных условий упрощает код. Каждое такое утверждение фактически представляет собой одну строку в таблице истинности. В альтернативных вариантах можно использовать сигнатуры функций.

Регулярные выражения "на лету"

Многие идиомы Perl используют то, что выражения возвращают значения:

say my $ext_num = my $extension = 42;

Этот немного корявый код показывает, как значение одного выражения можно использовать в другом.

Допустим, нужно извлечь имя из строки с именем и фамилией, используя заранее скомпилированное регулярное выражение:

my ($first_name) = $name =~ /($first_name_rx)/;

В списковом контексте успешное сопоставление возвращает список захваченных групп, первая из которых присваивается переменной $first_name.

Чтобы удалить все не-буквенные символы и создать пригодное имя пользователя:

(my $normalized_name = $name) =~ tr/A-Za-z//dc;

Неразрушающие замены

Более новый код может использовать модификатор /r для неразрушающих преобразований:

my $normalized_name = $name =~ tr/A-Za-z//dcr;

Скобки изменяют приоритет операторов так, чтобы сначала выполнилось присваивание, затем транслитерация.

Та же техника работает и с другими операторами изменения на месте:

my $age = 14;
(my $next_age = $age)++;
say "Мне $age лет, а в следующем году будет $next_age";

Унарные приведения типов

Типовая система Perl обычно сама правильно выбирает тип на основе оператора. Но иногда требуется явно подсказать Perl тип значения.

Привести к числу:

my $numeric_value = 0 + $value;

Привести к булеву значению:

my $boolean_value = !!$value;

Привести к строке:

my $string_value = '' . $value;

Такие приведения нужны редко, но иногда критичны.

Глобальные переменные

Perl предоставляет несколько суперглобальных переменных — они действительно глобальны. Их прямое или косвенное изменение может неожиданно повлиять на поведение программы.

Опытные разработчики помнят основные суперглобальные переменные, хотя полный их список найти можно в perldoc perlvar.

Управление суперглобальными переменными

Perl постепенно переносит глобальное поведение в лексическое. При необходимости изменения суперглобальной переменной следует использовать local в минимально возможной области видимости:

my $file; { local $/; $file = <$fh>; }

Локализация действует только внутри блока, что снижает риск нежелательных побочных эффектов.

Иногда нужно копировать значение сразу после чтения:

local $@;
eval { ... };
if (my $exception = $@) { ... }

Рекомендуется использовать Try::Tiny для надёжной обработки исключений.

Английские имена переменных

Модуль English предоставляет человекочитаемые имена для суперглобальных переменных. Импорт:

use English '-no_match_vars';

(Начиная с Perl 5.20, это уже не обязательно.)

Три переменные, связанные с регулярными выражениями ($&, $` и $'), ранее вызывали падение производительности, но с Perl 5.20 эта проблема устранена.

Полезные суперглобальные переменные

  • $/ — разделитель записей при чтении файлов.
  • $. — номер строки из последнего обработанного файлового дескриптора.
  • $| — управление буферизацией вывода.
  • @ARGV — список аргументов командной строки.
  • $! — код и текст последней ошибки системы.
  • $" — разделитель элементов списка при интерполяции.
  • %+ — именованные захваты при регулярных выражениях.
  • $@ — последнее перехваченное исключение.
  • $0 — имя текущей программы.
  • $$ — идентификатор процесса.
  • @INC — пути поиска модулей.
  • %SIG — обработчики сигналов ОС.

Альтернативы суперглобальным переменным

Операции ввода-вывода и обработка исключений — основные источники "действий на расстоянии" в коде. Чтобы защититься от сложной семантики правильной обработки исключений, используйте Try::Tiny.

Локализуйте и сразу копируйте значение переменной $!, чтобы избежать странного поведения, которое может возникнуть при неявных системных вызовах Perl.

Используйте модуль IO::File и его методы для работы с лексическими файловыми дескрипторами, чтобы минимизировать нежелательные глобальные изменения поведения ввода-вывода.
