Глава 9: Управление реальными программами

Управление реальными программами

Вы можете выучить много синтаксиса из книги, решая небольшие задачи. Но написание хорошего кода для решения реальных проблем требует больше дисциплины и понимания. Нужно уметь управлять кодом. Как узнать, что он работает? Как его организовать? Что делает его устойчивым к ошибкам? Что делает код чистым? Понятным? Поддерживаемым?

Modern Perl помогает ответить на все эти вопросы.

Тестирование

Вы уже тестировали свой код.

Если вы когда-либо запускали код, замечали ошибку, вносили исправления и запускали снова — вы тестировали код. Тестирование — это процесс проверки, что программа ведёт себя так, как задумано. Эффективное тестирование автоматизирует этот процесс.

Test::More

Основная единица тестирования — это проверка (assertion). Она отвечает на простой вопрос: ведёт ли себя код так, как задумано? Любое условие в программе может стать проверкой.

Тестирование Perl начинается с модуля Test::More и функции ok(). Она принимает два параметра: булево значение и описание теста:


use Test::More;

ok 1, 'единица должна быть истиной';
ok 0, '... а ноль — нет';
ok '', 'пустая строка должна быть ложью';
ok '!', '... а непустая строка — нет';

done_testing();

done_testing() сообщает Test::More, что все проверки выполнены. Это помогает обнаружить неожиданное завершение тестов.

Также можно заранее указать план тестов:


use Test::More tests => 4;

ok 1, 'единица должна быть истиной';
ok 0, '... а ноль — нет';
ok '', 'пустая строка должна быть ложью';
ok '!', '... а непустая строка — нет';

Запуск тестов

Этот тестовый файл создаёт вывод в формате TAP (Test Anything Protocol):


ok 1 - единица должна быть истиной
not ok 2 - ... а ноль — нет
# Failed test '... а ноль — нет'
# at truth_values.t line 4.
not ok 3 - пустая строка должна быть ложью
# Failed test 'пустая строка должна быть ложью'
# at truth_values.t line 5.
ok 4 - ... а непустая строка — нет
1..4
# Looks like you failed 2 tests of 4.

Для больших наборов тестов лучше использовать программу prove:


$ prove truth_values.t

Ошибки легко исправить:


ok !0, '... а ноль — нет';
ok !'', 'пустая строка должна быть ложью';

Теперь все тесты пройдут:


$ prove truth_values.t
truth_values.t .. ok
All tests successful.

Полезные опции prove: -j (параллельный запуск), -l (добавить lib/ в @INC), -r (рекурсивный запуск тестов в t/).


alias proveall='prove -j9 --state=slow,save -lr t'

Лучшие сравнения

Функция is() сравнивает два значения с помощью оператора eq:


use Test::More;

is 2 + 2, 4, 'сложение работает';
is 'pancake', 100, 'блины не число';

Ошибка будет содержать ожидаемое и полученное значения.

Проверка количества элементов:


my @cousins = qw( Rick Kristen Alex Kaycee Eric Corey );
is @cousins, 6, 'должно быть шесть кузенов';

isnt() проверяет неравенство через оператор ne.

Для строгих сравнений используйте cmp_ok():


cmp_ok 100, '<=', $cur_balance, 'должно быть не меньше 100';
cmp_ok $monkey, '==', $ape, 'числовые коды обезьян должны совпадать';

Проверка принадлежности классу с isa_ok():


my $chimpzilla = RobotMonkey->new;
isa_ok $chimpzilla, 'Robot';
isa_ok $chimpzilla, 'Monkey';

Проверка наличия методов через can_ok():


can_ok $chimpzilla, 'eat_banana';
can_ok $chimpzilla, 'transform', 'destroy_tokyo';

Глубокое сравнение структур с is_deeply():


use Clone;
my $numbers = [4, 8, 15, 16, 23, 42];
my $clonenums = Clone::clone($numbers);

is_deeply $numbers, $clonenums, 'клонирование прошло успешно';

Организация тестов

CPAN-пакеты содержат папку t/ с тестовыми файлами (.t).

  • Каждый .t файл соответствует одному .pm файлу
  • Или одной логической функции

При разработке отдельные файлы ускоряют проверку. Например, добавляя функцию огнедышащего Робо-обезьяны, можно запускать только файл t/robot_monkey/breathe_fire.t.

Другие модули для тестирования

Test::More использует тестовый движок Test::Builder, который управляет планом тестов и координирует вывод в формате TAP. Это позволяет использовать множество тестовых модулей CPAN вместе в одной программе:

  • Test::Fatal помогает тестировать, выбрасывает ли код исключения.
  • Test::MockObject и Test::MockModule позволяют эмулировать интерфейсы.
  • Test::WWW::Mechanize, Plack::Test и Test::WWW::Mechanize::PSGI тестируют веб-приложения без реального сервера.
  • Test::Database и DBICx::TestDatabase помогают тестировать базы данных.
  • Test::Class позволяет организовать тесты в классах. Test::Routine делает то же самое с помощью Moose.
  • Test::Differences сравнивает строки и структуры, а Test::LongString — длинные строки.
  • Test::Deep сравнивает вложенные структуры данных.
  • Devel::Cover показывает, сколько кода покрыто тестами.
  • Test::Most собирает в себе несколько полезных модулей для тестирования.

Подробнее о тестировании смотрите на проекте Perl QA: qa.perl.org.

Работа с предупреждениями

Генерация предупреждений

Используйте warn для вывода предупреждений:


warn 'Что-то пошло не так!';

Модуль Carp расширяет систему предупреждений Perl:


use Carp 'carp';

sub only_two_arguments {
    my ($lop, $rop) = @_;
    carp('Слишком много аргументов') if @_ > 2;
}

carp() указывает на место вызова функции, а cluck() ещё и выводит стек вызовов. Чтобы сделать все предупреждения подробными, запустите скрипт так:


$ perl -MCarp=verbose my_prog.pl

Для отладки чужого кода можно использовать модуль Carp::Always:


$ perl -MCarp::Always some_program.pl

Включение и отключение предупреждений

Флаг -w включает предупреждения глобально. Это устаревший способ. Современный — использовать pragma:


use warnings;

Глобальные флаги предупреждений

  • -W включает все предупреждения принудительно.
  • -X отключает все предупреждения принудительно.

Эти флаги влияют на глобальную переменную $^W.

Отключение категорий предупреждений

Можно отключить отдельные категории:


no warnings 'recursion';

Полный список категорий смотрите в perldoc perllexwarn.

Превращение предупреждений в ошибки

Чтобы сделать предупреждения фатальными:


use warnings FATAL => 'all';

Или только определённые категории:


use warnings FATAL => 'deprecated';

Будьте осторожны: новые версии Perl могут добавлять новые предупреждения, и код может начать падать.

Перехват предупреждений

Можно перехватывать предупреждения через %SIG:


{
    my $warning;
    local $SIG{__WARN__} = sub { $warning .= shift };
    # что-то рискованное
    ...
    say "Перехвачено предупреждение:\n$warning" if $warning;
}

Переменная %SIG глобальная, поэтому всегда локализуйте её.

Глава 9: Управление реальными программами

Регистрация собственных предупреждений

Прагма warnings::register позволяет создавать собственные категории предупреждений, которые пользователи смогут включать и отключать лексически:


    package Scary::Monkey;
    use warnings::register;

Теперь можно включить их через use warnings 'Scary::Monkey' и отключить через no warnings 'Scary::Monkey'.

Проверить активность предупреждений можно через warnings::enabled(), а вывести предупреждение — через warnings::warnif():


    package Scary::Monkey;
    use warnings::register;
    
    sub import {
        warnings::warnif('deprecated', 'пустой импорт из ' . __PACKAGE__ . ' устарел') unless @_;
    }

Подробнее смотрите в perldoc perllexwarn.

Файлы

Большинство программ взаимодействуют с реальным миром через файлы: чтение, запись и обработку текста.

Ввод и вывод

Дескриптор файла представляет состояние одного канала ввода-вывода. Perl стартует с тремя стандартными дескрипторами: STDIN, STDOUT и STDERR.

Открытие файла для чтения:


    open my $fh, '<', 'filename' or die "Cannot read '$filename': $!\n";

Основные режимы открытия файлов:

  • < — чтение;
  • > — запись (перезаписывание);
  • >> — добавление;
  • +< — чтение и запись;
  • -| — чтение из внешнего процесса;
  • |- — запись во внешний процесс.

Файлы можно открыть даже в скаляр:


    open my $read_fh, '<', \$fake_input;
    open my $write_fh, '>', \$captured_output;
    do_something_awesome($read_fh, $write_fh);

Смотрите perldoc perlopentut и perldoc perlfaq5 для подробностей.

Не забудьте про autodie

Для упрощения примеров предполагаем, что use autodie; включен. Иначе всегда проверяйте возврат системных вызовов.

Юникод, IO-слои и режимы файлов

Чтобы читать/писать в UTF-8:


    open my $in_fh, '<:encoding(UTF-8)', $infile;
    open my $out_fh, '>:encoding(UTF-8)', $outfile;

Два аргумента open()

Старый стиль объединял режим и имя файла:


    open my $fh, "> $file" or die "Cannot write to '$file': $!\n";

Используйте современный трёхаргументный open() для безопасности.

Специальный дескриптор DATA

Дескриптор DATA указывает на текст после __DATA__ или __END__ в исходнике. Можно читать его как обычный файл.

Чтение из файлов

Открытие файла и чтение построчно:


    open my $fh, '<', 'some_file';
    while (<$fh>) {
        chomp;
        say "Прочитана строка '$_'";
    }

В скалярном контексте readline читает строку за раз. Важно использовать while, а не for, чтобы не читать весь файл в память.

Чтение бинарных файлов

Для работы с бинарными данными (например, изображениями) используйте binmode перед операциями ввода-вывода.

Запись в файлы

Печать в файл:


    open my $out_fh, '>', 'output_file.txt';
    print $out_fh "Вот строка текста\n";
    say $out_fh "... и ещё одна строка";

Рекомендация: всегда обрамляйте дескрипторы в фигурные скобки для ясности:


    print {$out_fh} "Текст\n";

Закрытие файлов

Когда работа с файлом окончена, закройте его явно:


    use autodie qw(open close);
    
    open my $fh, '>', $file;
    ...
    close $fh;

Явное закрытие позволяет отлавливать ошибки, например, нехватку места на диске.

Специальные переменные для работы с файлами

Для каждой прочитанной строки Perl увеличивает переменную $. , которая служит счётчиком строк.

readline использует текущее значение $/ в качестве разделителя строк. Обычно это символы перевода строки, соответствующие платформе, но $/ можно установить в любую последовательность символов.

Например, чтобы читать по записям, разделённым двумя пустыми строками, установите:


    local $/ = "\n\n";

Переменная $| управляет буферизацией вывода. Установите её в ненулевое значение, чтобы вывод происходил сразу после каждой записи:


    $| = 1;

Автоматическое сбрасывание буфера

Файлы по умолчанию используют полную буферизацию. STDOUT при подключении к терминалу — построчную.

Для управления буферизацией на уровне файлового дескриптора используйте метод autoflush():


    open my $fh, '>', 'pecan.log';
    $fh->autoflush(1);

Каталоги и пути

Работа с каталогами схожа с работой с файлами, но запись в каталог невозможна. Откройте каталог через opendir:


    opendir my $dirh, '/home/monkeytamer/tasks/';

Чтение каталога:


    while (my $file = readdir $dirh) {
        ...
    }

Или прочитайте весь каталог в массив:


    my @files = readdir $dirh;

Пропустите скрытые файлы (начинающиеся с точки):


    while (readdir $dirh) {
        next if /^\./;
        say "Найдена задача $_!";
    }

Манипуляции с путями

Perl использует Unix-подобные пути независимо от ОС. Для кроссплатформенной работы используйте модуль File::Spec или более удобный Path::Class:


    use Path::Class;
    
    my $meals = dir('tasks', 'cooking');
    my $file = file('tasks', 'health', 'robots.txt');

Манипуляции с файлами

Проверка существования файла:


    say 'Присутствует!' if -e $filename;

Другие тесты:

  • -f — обычный файл
  • -d — каталог
  • -r — файл доступен для чтения
  • -s — файл непустой

Переименование файла:


    rename 'death_star.txt', 'carbon_sink.txt';

Удаление файла:


    unlink 'useless_file.txt';

Текущий рабочий каталог:


    use Cwd;
    
    say cwd();

Изменение каталога:


    chdir '/new/path';

Модули

Модуль — это файл Perl-кода, который можно загрузить через use или require. Он должен возвращать истину в конце.

Загрузка модуля:


    use StrangeMonkey;

Perl ищет StrangeMonkey.pm в директориях @INC. Для StrangeMonkey::Persistence ищется StrangeMonkey/Persistence.pm.

Полезные команды perldoc

  • perldoc -l Module::Name — путь к файлу
  • perldoc -lm Module::Name — путь без форматирования
  • perldoc -m Module::Name — содержимое файла

Организация кода с модулями

Даже без ООП полезно разделять код на модули. Это:

  • Разделяет логические части системы
  • Создаёт API
  • Упрощает организацию кода
  • Позволяет переиспользовать код

Использование и импорт

При загрузке модуля через use Perl вызывает его import() с переданными аргументами.


    use strict;
    use File::Spec::Functions 'tmpdir';
    use feature qw(say unicode_strings);

no вызывает unimport() модуля:


    use strict;
    {
        no strict 'refs';
    }

Эквивалент загрузки модуля через BEGIN:


    BEGIN {
        require 'Module/Name.pm';
        Module::Name->import(qw( list of arguments ));
    }

Отсутствующие методы, которые не вызывают ошибок

Если в модуле нет import() или unimport(), Perl не вызовет ошибку. Эти методы действительно являются необязательными.

Вы можете вызвать import() и unimport() напрямую, хотя вне блока BEGIN это редко имеет смысл; после завершения компиляции их эффекты могут быть незначительными (так как обычно эти методы влияют на процесс компиляции через импорт символов или переключение фич).

Портируемые программы соблюдают чувствительность к регистру, даже если технически могут обойтись без этого.

И use, и require чувствительны к регистру. Perl различает strict и Strict, но ваша операционная система и файловая система могут не различать. Если написать use Strict; вместо strict на регистро-независимой системе, Perl загрузит Strict.pm, но ничего не произойдет при попытке вызвать Strict->import() (так как strict.pm определяет пакет strict, а не Strict).

Экспортирование

Модуль может сделать доступными глобальные символы пакета для других пакетов через процесс, называемый экспортированием — обычно через явный или неявный вызов import().

Стандартный способ экспортировать символы — использовать модуль Exporter. Он полагается на глобальные переменные пакета, такие как @EXPORT_OK и @EXPORT, которые определяют экспортируемые символы.

Пример модуля StrangeMonkey::Utilities:


            package StrangeMonkey::Utilities;
            use Exporter 'import';
            
            our @EXPORT_OK = qw( round translate screech );

Другой код может использовать этот модуль и импортировать выбранные функции. Можно также экспортировать переменные:


            push @EXPORT_OK, qw( $spider $saki $squirrel );

Экспорт символов по умолчанию:


            our @EXPORT = qw( monkey_dance monkey_sleep );

Чтобы загрузить модуль без импорта символов:


            use StrangeMonkey::Utilities ();

Функции всегда можно вызывать с полным именем:


            StrangeMonkey::Utilities::screech();

Упрощённое экспортирование

Модуль Sub::Exporter с CPAN предоставляет более удобный способ экспортировать функции без использования глобальных переменных пакета и с дополнительными возможностями. Однако он экспортирует только функции. Модуль Moose::Exporter предоставляет мощные механизмы для систем на базе Moose, но имеет крутую кривую обучения.

Дистрибутивы

Дистрибутив — это набор метаданных и модулей, собранный в единую единицу для распространения, тестирования и установки. Самый лёгкий способ работать с Perl-кодом — следовать стандартам CPAN.

Стандарты CPAN описывают упаковку, разрешение зависимостей, установку кода и документации, тестирование и управление репозиториями. Эти стандарты возникли благодаря опыту тысяч разработчиков.

Хорошо оформленный дистрибутив включает:

  • Build.PL или Makefile.PL — скрипт для сборки и установки.
  • MANIFEST — список всех файлов дистрибутива.
  • META.yml и/или META.json — метаданные о дистрибутиве.
  • README — описание проекта и лицензия.
  • lib/ — директория модулей Perl.
  • t/ — директория с тестами.
  • Changes — журнал изменений.

Каждый дистрибутив должен иметь уникальное имя и номер версии. Публичный сервис CPANTS оценивает качество дистрибутивов.

Инструменты CPAN для управления дистрибутивами

Perl включает несколько инструментов для работы с дистрибутивами:

  • CPAN.pm — официальный клиент CPAN.
  • ExtUtils::MakeMaker — система для сборки, тестирования и установки дистрибутивов.
  • Test::More — базовый модуль для написания тестов.
  • TAP::Harness и prove — запуск и интерпретация тестов.

Дополнительные полезные модули с CPAN:

  • App::cpanminus — лёгкий CPAN-клиент без конфигурации.
  • App::perlbrew — управление несколькими установками Perl.
  • CPAN::Mini — создание локального зеркала CPAN.
  • Dist::Zilla — автоматизация сборки дистрибутивов.
  • Test::Reporter — отправка результатов тестов авторам модулей.
  • Carton и Pinto — управление зависимостями проектов.
  • Module::Build — альтернатива MakeMaker на чистом Perl.

Проектирование дистрибутивов

Процесс проектирования дистрибутива мог бы занять целую книгу (например, «Writing Perl Modules for CPAN» Сэма Трегора), но несколько принципов помогут вам начать. Используйте утилиты вроде Module::Starter или Dist::Zilla. Первоначальная цена обучения их конфигурации и правилам может показаться высокой, но выгода от правильной настройки (и в случае Dist::Zilla — автоматического обновления) избавит вас от рутинной работы.

Дистрибутив должен следовать нескольким не связанным с кодом правилам:

  • Каждый дистрибутив выполняет одну, чётко определённую задачу. Она может включать в себя объединение нескольких связанных дистрибутивов в один установочный пакет. Разбивайте своё ПО на отдельные дистрибутивы для правильного управления зависимостями и соблюдения инкапсуляции.
  • Каждый дистрибутив имеет единственный номер версии. Номера версий всегда должны увеличиваться. Политика семантического версионирования (semver.org) разумна и совместима с подходом Perl.
  • Каждый дистрибутив предоставляет чётко определённый API. Комплексный автоматизированный набор тестов может гарантировать его стабильность между версиями. Локальные зеркала CPAN позволяют использовать инфраструктуру CPAN для тестирования ваших дистрибутивов и их зависимостей.
  • Тесты дистрибутива должны быть полезными и воспроизводимыми. CPAN-инфраструктура поддерживает автоматизированную отправку результатов тестов — используйте её!
  • Интерфейсы должны быть простыми и эффективными. Избегайте глобальных символов и экспорта по умолчанию; позволяйте пользователям импортировать только то, что им нужно. Не загрязняйте их пространства имён.

Пакет UNIVERSAL

Встроенный пакет UNIVERSAL — это предок всех других пакетов в Perl, что делает его финальным родителем в объектно-ориентированном смысле. UNIVERSAL предоставляет несколько методов для использования, наследования или переопределения.

Метод VERSION()

Метод VERSION() возвращает значение переменной $VERSION вызывающего пакета или класса. Если передать версию как параметр, метод выбросит исключение, если версия будет меньше заданной.


my $hm = HowlerMonkey->new;
say HowlerMonkey->VERSION;     # печатает 1.23
say $hm->VERSION;              # печатает 1.23
say $hm->VERSION( 0.0 );        # печатает 1.23
say $hm->VERSION( 1.23 );       # печатает 1.23
say $hm->VERSION( 2.0 );        # исключение!

Переопределять VERSION() почти никогда не требуется.

Метод DOES()

Метод DOES() используется для работы с ролями. Он принимает объект и имя роли и возвращает истину, если объект поддерживает эту роль через наследование, делегирование, композицию или другие механизмы.

Реализация по умолчанию вызывает isa(), поскольку наследование — один из способов реализации роли. Пример:


say Cappuchin->DOES('Monkey');     # печатает 1
say $cappy->DOES('Monkey');        # печатает 1
say Cappuchin->DOES('Invertebrate'); # печатает 0

Переопределите DOES(), если вручную реализуете роль.

Метод can()

Метод can() принимает строку с именем метода или функции и возвращает ссылку на неё, если она существует, либо ложное значение в противном случае. Вызывать можно на классе, объекте или имени пакета.

Пример:


if (my $meth = SpiderMonkey->can('screech')) {
    ...
}

И распространённый паттерн:


if (my $meth = $sm->can('screech')) {
    $sm->$meth();
}

Пример использования вместе с Class::Load:


use Class::Load;
die "Couldn't load $module!" unless load_class($module);

if (my $register = $module->can('register')) {
    $register->();
}

Полезные модули: Class::Load для загрузки классов, Module::Pluggable для создания систем плагинов.

Метод isa()

Метод isa() принимает строку с именем класса или базового типа (SCALAR, ARRAY, HASH, Regexp, IO или CODE) и проверяет, принадлежит ли объект или класс к нему.

Примеры:


say $pepper->isa('Monkey');    # печатает 1
say $pepper->isa('Mammal');    # печатает 1
say $pepper->isa('HASH');      # печатает 1
say Monkey->isa('Mammal');     # печатает 1
say $pepper->isa('Dolphin');   # печатает 0
say $pepper->isa('ARRAY');     # печатает 0
say Monkey->isa('HASH');       # печатает 0

Любой класс может переопределить isa(). Это полезно для мок-объектов (Test::MockObject и Test::MockModule) или для работы с кодом без поддержки ролей.

Существует ли класс?

Хотя UNIVERSAL::isa() и UNIVERSAL::can() являются методами (Эквивалентность методов и функций, стр. 259), безопасно использовать can() как функцию только для проверки существования класса в Perl. Если UNIVERSAL::can($classname, 'can') возвращает истинное значение, это означает, что кто-то где-то определил класс с именем $classname. Этот класс может быть непригодным для использования, но он существует.

Расширение UNIVERSAL

Есть соблазн добавить дополнительные методы в UNIVERSAL, чтобы они были доступны всем другим классам и объектам Perl. Избегайте этого искушения: глобальное поведение может вызвать тонкие побочные эффекты, особенно в коде, который вы не писали и не поддерживаете.

Тем не менее, иногда допустимо использовать UNIVERSAL для целей отладки или исправления неправильного поведения по умолчанию. Например, модуль UNIVERSAL::ref делает почти бесполезный оператор ref() полезным. Модули UNIVERSAL::can и UNIVERSAL::isa помогают отлавливать ошибки анти-полиморфизма (Эквивалентность методов и функций, стр. 259). Perl::Critic может обнаруживать такие и другие проблемы.

Вне очень тщательно контролируемого кода и очень специфических прагматичных ситуаций нет причин помещать код непосредственно в UNIVERSAL, особенно учитывая наличие альтернативных подходов к проектированию.

Генерация кода

Новички часто пишут больше кода, чем необходимо. Они начинают с длинных списков процедурного кода, затем открывают для себя функции, параметры, объекты и–возможно–функции высшего порядка и замыкания.

По мере развития навыков вы будете писать меньше кода для решения тех же задач. Вы будете использовать лучшие абстракции и писать более обобщённый код. Вы сможете переиспользовать код–и когда добавление функций будет сопровождаться удалением строк кода, это будет настоящим успехом.

Создание программ, которые пишут программы за вас–метапрограммирование или генерация кода–позволяет строить переиспользуемые абстракции. Хотя это может привести к хаосу, с его помощью можно создать по-настоящему впечатляющие вещи. Например, именно благодаря метапрограммированию возможен Moose (Moose, стр. 159).

eval

Самая простая техника генерации кода — собрать строку с валидным Perl-кодом и скомпилировать её с помощью строкового eval. В отличие от блочного eval для перехвата исключений, строковый eval компилирует строку в текущей области видимости, включая пакет и лексические переменные.

Обычное применение этой техники — создание резервного варианта в случае невозможности загрузить опциональную зависимость:


eval { require Monkey::Tracer } or eval 'sub Monkey::Tracer::log {}';

Если Monkey::Tracer недоступен, создаётся пустая функция log(). Однако правильно использовать eval непросто: нужно внимательно работать с кавычками, особенно при интерполяции переменных:


sub generate_accessors {
    my ($methname, $attrname) = @_;
    eval <<"END_ACCESSOR";
sub get_$methname {
    my \$self = shift;
    return \$self->{$attrname};
}
sub set_$methname {
    my (\$self, \$value) = \@_;
    \$self->{$attrname} = \$value;
}
END_ACCESSOR
}

Не забудьте про экранирование символов! Иначе возможны ошибки в коде и некорректная подсветка синтаксиса.

Параметризованные замыкания

Замыкания позволяют создавать код с параметрами без дополнительных eval:


sub generate_accessors {
    my $attrname = shift;
    my $getter = sub {
        my $self = shift;
        return $self->{$attrname};
    };
    my $setter = sub {
        my ($self, $value) = @_;
        $self->{$attrname} = $value;
    };
    return $getter, $setter;
}

Это решение избегает проблем с кавычками и компилируется только один раз, экономя память. Различие лишь в лексическом привязывании переменной $attrname.

Установка в таблицу символов

Установка функций в таблицу символов выполняется так:


my ($get, $set) = generate_accessors('pie');
no strict 'refs';
*{'get_pie'} = $get;
*{'set_pie'} = $set;

Будьте осторожны: если вы присваиваете сразу при определении функции, может возникнуть скрытая ошибка:


no strict 'refs';
*{$methname} = sub { ... }; # плохой стиль

Правильный способ:


{
    my $sub = sub { ... };
    no strict 'refs';
    *{$methname} = $sub;
}

Упрощение работы с таблицей символов

Используйте модуль Package::Stash с CPAN для упрощения работы с таблицами символов.

Манипуляции на этапе компиляции

Код, созданный через строковый eval, компилируется в момент выполнения программы. Чтобы создать код на этапе компиляции, оберните генерацию в блок BEGIN:


sub make_accessors { ... }
BEGIN {
    for my $accessor (qw(age name weight)) {
        my ($get, $set) = make_accessors($accessor);
        no strict 'refs';
        *{"get_$accessor"} = $get;
        *{"set_$accessor"} = $set;
    }
}

При использовании use Perl оборачивает весь импортируемый код в неявный BEGIN. При require этого не происходит.

Подводные камни компиляции и присваивания

Будьте внимательны: связывание имени переменной и её значения происходит в разные моменты:


use UNIVERSAL::require;
my $wanted_package = 'Monkey::Jetpack';
BEGIN {
    $wanted_package->require;
    $wanted_package->import;
}

Этот код сломается, так как в момент исполнения BEGIN переменная $wanted_package ещё не получила значение. Следует использовать только значения, доступные уже на этапе компиляции.

Class::MOP

В отличие от установки ссылок на функции для заполнения пространств имён и создания методов, в Perl нет простого способа динамически создавать классы. На помощь приходит Moose со своей встроенной библиотекой Class::MOP. Она предоставляет протокол метаобъектов (MOP) — механизм создания и управления объектной системой через объекты и методы.

Вместо того чтобы писать хрупкий код со строковыми eval или вручную ковыряться в таблицах символов, вы можете манипулировать сущностями и абстракциями программы с помощью объектов.

Создание класса:


use Class::MOP;
my $class = Class::MOP::Class->create('Monkey::Wrench');

Добавление атрибутов и методов при создании:


my $class = Class::MOP::Class->create(
    'Monkey::Wrench' => (
        attributes => [
            Class::MOP::Attribute->new('$material'),
            Class::MOP::Attribute->new('$color'),
        ],
        methods => {
            tighten => sub { ... },
            loosen => sub { ... },
        },
    ),
);

Или позже, через метакласс:


$class->add_attribute(
    experience => Class::MOP::Attribute->new('$xp')
);
$class->add_method(bash_zombie => sub { ... });

MOP даёт вам возможность не только создавать новые сущности во время выполнения программы, но и заглядывать внутрь существующего (MOP-совместимого) кода:


my @attrs = $class->get_all_attributes;
my @meths = $class->get_all_methods;

Аналогично, Class::MOP::Attribute и Class::MOP::Method позволяют создавать, управлять и инспектировать атрибуты и методы.

Перегрузка

Perl не является всецело объектно-ориентированным языком. Его основные типы данных (скаляры, массивы, хеши) не являются объектами с методами. Однако вы можете контролировать поведение своих собственных классов и объектов при приведении типов или в контекстах. Это и есть перегрузка.

Перегрузка — мощная, но тонкая вещь. Например, объект в логическом контексте по умолчанию считается истинным, если вы явно не перегрузите это поведение. Иногда это нужно, например, при реализации паттерна "Null Object" (Null Object Pattern).

Перегрузка часто используемых операций

Прагма overload позволяет ассоциировать функции с перегружаемыми операциями. Пара "операция => функция" передаётся в use overload. Класс Null, который всегда возвращает ложь в логическом контексте, может выглядеть так:


package Null {
    use overload 'bool' => sub { 0 };
    ...
}

Добавим строковое представление:


package Null {
    use overload
        'bool' => sub { 0 },
        '""'   => sub { '(null)' };
}

Числовая перегрузка сложнее, потому что арифметические операторы являются бинарными (Арность, стр. 98). Нужно определить, какая перегрузка имеет приоритет. Чтобы избежать путаницы, проще всего перегрузить приведение к числу ('0+') и включить fallback:


package Null {
    use overload
        'bool' => sub { 0 },
        '""'   => sub { '(null)' },
        '0+'   => sub { 0 },
        fallback => 1;
}

Установка fallback в значение истина позволяет Perl использовать другие определённые перегрузки при необходимости, а если их нет — работать как обычно, без перегрузок. Это часто предпочтительный вариант.

Без fallback Perl будет использовать только явно определённые перегрузки и выбросит исключение при попытке выполнить неперегруженную операцию.

Перегрузка и наследование

Подклассы наследуют перегрузки от родительских классов. Они могут переопределить поведение двумя способами:

  • Определить перегрузки через ссылку на функцию, если родитель тоже использует ссылки.
  • Или определить перегрузки через имя метода, чтобы переопределить их в потомках.

Например:


package Null {
    use overload
        'bool' => 'get_bool',
        '""'   => 'get_string',
        '0+'   => 'get_num',
        fallback => 1;

    sub get_bool { 0 }
}

Подкласс может изменить только нужное поведение, например:


package Null::ButTrue {
    use parent 'Null';
    sub get_bool { 1 }
}

Применение перегрузки

Перегрузка может показаться заманчивым инструментом для создания символьных сокращений для новых операций. Дистрибутив CPAN IO::All доводит эту идею до предела, создавая простой и элегантный API. Однако на каждый блестящий API, доведённый до совершенства через правильное использование перегрузки, приходится десяток беспорядков. Иногда лучший код избегает хитростей в пользу простоты.

Переопределение операций сложения, умножения и даже конкатенации в классе Matrix имеет смысл, потому что для этих операций существует устоявшееся обозначение. Для новой предметной области без такого устоявшегося обозначения перегрузка — плохая идея. То же касается случаев, когда приходится "жмуриться", чтобы сопоставить существующие операторы Perl с другим синтаксисом.

В книге Damian Conway "Perl Best Practices" предлагается ещё одно применение перегрузки: предотвращение случайного неправильного использования объектов. Например, перегрузка приведения к числу с вызовом croak() для объектов, которые не имеют разумного численного представления, может помочь найти и исправить настоящие ошибки.

Тейнтинг

Некоторые возможности Perl помогают писать безопасные программы. Эти инструменты не заменяют осторожного мышления и планирования, но они поощряют осмотрительность и понимание, помогая избежать тонких ошибок.

Режим тейнта (taint mode) — это метка, прикрепляемая ко всем данным, поступающим извне программы. Любые данные, полученные на основе тейнтованных данных, также считаются тейнтованными.

Вы можете использовать тейнтованные данные внутри программы, но если вы попытаетесь использовать их для воздействия на внешний мир небезопасным способом, Perl выбросит фатальное исключение.

Использование режима тейнта

Подробное объяснение режима тейнта можно найти в perldoc perlsec.

Запустите вашу программу с аргументом -T на командной строке, чтобы включить режим тейнта. Если вы добавили этот аргумент в шебанг-строку (#!), необходимо запускать скрипт напрямую. Если запустить его как perl mytaintedapp.pl без флага -T, Perl завершится с ошибкой — к моменту обработки шебанг-строки будет уже поздно тейнтовать данные из %ENV.

Источники тейнта

Тейнт может поступать из двух источников: ввода из файлов и операционной среды программы. Ввод из файлов включает любые данные, читаемые из файлов или получаемые от пользователей через сеть. Окружение включает аргументы командной строки, переменные окружения и результаты системных вызовов. Даже чтение содержимого директории через readdir приводит к тейнтованию данных.

Функция tainted() из модуля Scalar::Util возвращает истину, если аргумент тейнтован:


die 'О нет! Данные тейнтованы!' if Scalar::Util::tainted( $sketchy_data );

Удаление тейнта из данных

Чтобы удалить тейнт, нужно извлечь проверенные данные через регулярное выражение с захватом. Только данные из захваченных групп будут считаться безопасными. Например, для проверки телефонного номера США:


die 'Номер всё ещё тейнтован!' unless $number =~ /(\(\d{3}\) \d{3}-\d{4})/;
my $safe_number = $1;

Чем более специфичным будет ваше регулярное выражение, тем безопаснее будет программа. Подход "запретить определённые вещи" опасен — лучше запретить что-то безопасное, чем пропустить вредное.

Удаление тейнта из окружения

Переменная %ENV содержит переменные окружения операционной системы. Эти данные считаются тейнтованными, так как их легко изменить извне. Безопасная программа должна удалить потенциально опасные ключи и явно установить $ENV{PATH}:


delete @ENV{ qw( IFS CDPATH ENV BASH_ENV ) };
$ENV{PATH} = '/path/to/app/binaries/';

Если не установить $ENV{PATH} явно, Perl пожалуется на его небезопасность. Это связано с тем, что наличие текущего каталога или изменяемых директорий в пути позволяет злоумышленнику заменить исполняемые файлы.

По тем же причинам в режиме тейнта @INC по умолчанию не содержит текущего каталога. Также игнорируются переменные окружения PERL5LIB и PERLLIB. Добавлять каталоги с библиотеками следует через pragma lib или флаг -I.

Подводные камни тейнта

Режим тейнта либо включён, либо выключен — промежуточных состояний нет. Иногда это побуждает людей использовать слишком разрешающие регулярные выражения для удаления тейнта, создавая иллюзию безопасности. Проверяйте правила удаления тейнта внимательно.

К сожалению, не все модули CPAN корректно обрабатывают тейнтованные данные. Это ошибка, которую авторам стоит воспринимать серьёзнее. Для обеспечения постепенного перехода можно использовать флаг -t, который переводит ошибки тейнта в предупреждения. Это не полноценная замена режиму -T, но помогает постепенно исправлять существующие программы.
