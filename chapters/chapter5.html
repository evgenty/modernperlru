Глава 5: Функции

Функции

Функция (или подпрограмма) в Perl — это отдельная, инкапсулированная единица поведения. Программа состоит из таких "чёрных ящиков", где взаимодействие функций управляет потоком выполнения. Функция может иметь имя, принимать входные данные и возвращать результат.

Объявление функций

Для объявления используйте встроенное слово sub:

sub greet_me { ... }

Можно также объявить функцию заранее (forward declaration):

sub greet_sun;

Вызов функций

Вызов функции осуществляется с использованием скобок:

greet_me( 'Jack', 'Tuxie', 'Brad' );
greet_me( 'Snowy' );
greet_me();

Скобки не обязательны, но их лучше использовать для ясности.

Аргументы могут быть выражениями:

greet_me( $name );
greet_me( @authors );
greet_me( %editors );
greet_me( get_readers() );

Параметры функций

Все параметры передаются через массив @_:

sub greet_one {
    my ($name) = @_;
    say "Hello, $name!";
}

sub greet_all {
    say "Hello, $_!" for @_;
}

Можно использовать shift или доступ по индексу:

sub greet_one_shift {
    my $name = shift;
    say "Hello, $name!";
}

sub greet_two_list_assignment {
    my ($hero, $sidekick) = @_;
    say "Well if it isn't $hero and $sidekick. Welcome!";
}

sub greet_one_indexed {
    my $name = $_[0];
    say "Hello, $name!";
}

Ошибочный пример с использованием @_ в скалярном контексте:

sub bad_greet_one {
    my $name = @_; # ошибка
    say "Hello, $name; you look numeric today!";
}

Рекомендуемый способ:

my ($left_value, $operation, $right_value) = @_;

Пример делегирования параметров:

sub delegated_method {
    my $self = shift;
    say 'Calling delegated_method()';
    $self->delegate->delegated_method( @_ );
}

Реальные сигнатуры функций

Начиная с Perl 5.20, доступны экспериментальные сигнатуры функций (требуется:

use experimental 'signatures';

Пример с одной переменной:

sub greet_one($name) {
    say "Hello, $name!";
}

Эквивалент традиционной записи:

sub greet_one {
    die "Too many arguments" if @_ < 1;
    die "Too few arguments" if @_ > 1;
    my $name = shift;
    say "Hello, $name!";
}

Можно задать значение по умолчанию:

sub greet_one($name = 'Bruce') {
    say "Hello, $name!";
}

Агрегатные параметры в конце списка:

sub greet_all($leader, @everyone) {
    say "Hello, $leader!";
    say "Hi also, $_." for @everyone;
}

sub make_nested_hash($name, %pairs) {
    return { $name => \%pairs };
}

Функция без параметров:

sub no_gifts_please() {
    say 'I have too much stuff already.';
}

Попытка передать аргументы в такую функцию вызовет исключение "Too many arguments for subroutine".

Дополнительно

Подробности о сигнатурах ищите в perldoc perlsub, в разделе "Signatures".

Есть альтернативы на CPAN: Method::Signatures (начиная с Perl 5.8) и Kavorka (с Perl 5.14).

Стоит ли использовать сигнатуры?

Несмотря на экспериментальный статус встроенных сигнатур функций и дополнительные зависимости модулей с CPAN, все эти варианты могут сделать ваш код немного короче, понятнее и удобнее для поддержки.

Экспериментируйте и выбирайте, что лучше подходит вам и вашей команде. Даже простое использование позиционных параметров уже даёт ощутимые преимущества.

Флаттенинг

Перемещение списка аргументов в @_ происходит на стороне вызывающего кода. Например, передача хэша превращает его в список пар ключ/значение:

my %pet_names_and_types = (
    Lucky => 'dog',
    Rodney => 'dog',
    Tuxedo => 'cat',
    Petunia => 'cat',
    Rosie => 'dog',
);
show_pets( %pet_names_and_types );

sub show_pets {
    my %pets = @_;
    while (my ($name, $type) = each %pets) {
        say "$name is a $type";
    }
}

Порядок элементов может варьироваться, но всегда ключ следует перед соответствующим значением. Это поведение удобно, но требует осторожности при смешивании скаляров и агрегатов в параметрах.

Например, для фильтрации по типу животного:

sub show_pets_by_type {
    my ($type, %pets) = @_;
    while (my ($name, $species) = each %pets) {
        next unless $species eq $type;
        say "$name is a $species";
    }
}

my %pet_names_and_types = (
    Lucky => 'dog',
    Rodney => 'dog',
    Tuxedo => 'cat',
    Petunia => 'cat',
    Rosie => 'dog',
);

show_pets_by_type( 'dog', %pet_names_and_types );
show_pets_by_type( 'cat', %pet_names_and_types );
show_pets_by_type( 'moose', %pet_names_and_types );

С использованием сигнатур можно упростить:

sub show_pets_by_type($type, %pets) {
    ...
}

Захват параметров ("Slurping")

Когда происходит присваивание списка, оставшиеся элементы жадно захватываются:

sub show_pets_by_type {
    my $type = pop;
    my %pets = @_;
    ...
}

Но это ухудшает читаемость. Чтобы избежать нежелательного флаттенинга агрегатов, используйте ссылки.

Алиасинг

@_ в Perl не копирует аргументы, а создаёт ссылки на переданные значения. Если вы измените @_ напрямую, это изменит оригинальные данные.

Пример:

sub modify_name {
    $_[0] = reverse $_[0];
}

my $name = 'Orange';
modify_name( $name );
say $name;
# выведет egnarO

Будьте осторожны: либо сразу распаковывайте @_ в локальные переменные, либо чётко документируйте изменения аргументов.

Функции и пространства имён

Каждая функция принадлежит пространству имён (Package). Функции без явного объявления пространства находятся в main.

Вы можете явно указать пространство имён при объявлении функции:

sub Extensions::Math::add { ... }

Perl создаст пространство автоматически. Пространства имён остаются открытыми для изменений во время выполнения программы.

Вызов функций внутри одного пространства можно делать по короткому имени. Для обращения к функциям из другого пространства нужно использовать полное имя:

package main;
Extensions::Math::add( $scalar, $vector );

Лексические функции

В Perl 5.18 появилась экспериментальная возможность объявления функций, видимых только в пределах лексической области. Подробнее — в perldoc perlsub ("Lexical Subroutines").

Импорт функций

Когда вы используете use, Perl автоматически вызывает метод import() модуля:

use strict;

Это аналогично:

BEGIN {
    require strict;
    strict->import();
}

Примеры с аргументами:

use strict 'refs';
use strict qw( subs vars );

Их эквивалент через require и ручной вызов import:

BEGIN {
    require strict;
    strict->import('refs');
    strict->import('subs', 'vars');
}

use оборачивает код в BEGIN-блок, чтобы импортированные функции были доступны компилятору сразу.

Отчёты об ошибках

Для получения информации о месте вызова функции используйте caller(). Без аргументов caller() возвращает пространство имён, имя файла и номер строки вызова:

package main;
main();

sub main {
    show_call_information();
}

sub show_call_information {
    my ($package, $file, $line) = caller();
    say "Called from $package in $file:$line";
}

Если передать caller() число, можно получить информацию об уровне выше:

sub show_call_information {
    my ($package, $file, $line, $func) = caller(0);
    say "Called $func from $package in $file:$line";
}

Модуль Carp использует caller для улучшения сообщений об ошибках. Вместо die в библиотечном коде используйте croak(), чтобы ошибка выглядела как вызванная внешним кодом. Для предупреждений используйте carp().

Используйте caller (или Carp) для валидации параметров и проверки предусловий в функциях, чтобы указывать на ошибки вызывающего кода.

Валидация аргументов

Хотя Perl старается "делать то, что вы хотите", у него мало встроенных механизмов проверки аргументов функций. Чтобы проверить количество аргументов, используйте скалярный контекст для @_:

sub add_numbers {
    croak 'Expected two numbers, received: ' . @_ unless @_ == 2;
    ...
}

Функция croak() корректно укажет ошибку с точки зрения вызывающего кода.

Проверка типов сложнее из-за особенностей преобразований типов в Perl. Для надёжной проверки параметров используйте CPAN-модули вроде Params::Validate.

Продвинутые функции

Контекст выполнения

Функции могут определять, в каком контексте их вызвали: void, scalar или list. Для этого используется wantarray:

sub context_sensitive {
    my $context = wantarray();
    return qw( List context ) if $context;
    say 'Void context' unless defined $context;
    return 'Scalar context' unless $context;
}

context_sensitive();
say my $scalar = context_sensitive();
say context_sensitive();

wantarray может быть полезен для избежания лишних вычислений в void-контексте. Иногда удобнее писать отдельные функции для разных контекстов.

Дополнительно: на CPAN доступны модули Want и Contextual::Return для более мощного управления контекстом выполнения.

Рекурсия

Рассмотрим задачу поиска элемента в отсортированном массиве через деление пополам:

use Test::More;
my @elements = ( 1, 5, 6, 19, 48, 77, 997, 1025, 7777, 8192, 9999 );

ok elem_exists( 1, @elements ), 'found first element in array';
ok elem_exists( 9999, @elements ), 'found last element in array';
ok ! elem_exists( 998, @elements ), 'did not find missing element';
ok ! elem_exists( -1, @elements ), 'did not find missing element';
ok ! elem_exists( 10000, @elements ), 'did not find missing element';
ok elem_exists( 77, @elements ), 'found middle element';
ok elem_exists( 48, @elements ), 'found lower half element';
ok elem_exists( 997, @elements ), 'found upper half element';

done_testing();

Пример рекурсивной функции elem_exists:

sub elem_exists {
    my ($item, @array) = @_;
    return unless @array;
    my $midpoint = int( (@array / 2) - 0.5 );
    my $miditem = $array[ $midpoint ];
    return 1 if $item == $miditem;
    return if @array == 1;
    return elem_exists($item, @array[0 .. $midpoint]) if $item < $miditem;
    return elem_exists($item, @array[$midpoint + 1 .. $#array]);
}

Каждый вызов создаёт новый стековый фрейм с отдельной лексической средой. Поэтому важно наличие условия остановки рекурсии.

Любую рекурсивную программу можно переписать без рекурсии, но метод "разделяй и властвуй" остаётся удобным решением многих задач.

Для дальнейшего изучения рекурсии и функционального программирования в Perl рекомендуем книгу Higher Order Perl (доступна бесплатно).

Лексические переменные

Каждый вызов функции создаёт отдельную область видимости и стековый фрейм. Хотя определение elem_exists() создаёт один набор лексических переменных ($item, @array, $midpoint, $miditem), каждый вызов функции хранит их значения независимо.

Таким образом, функция может безопасно вызывать саму себя:

use Carp 'cluck';

sub elem_exists {
    my ($item, @array) = @_;
    cluck "[$item] (@array)";
    ...
}

Хвостовая рекурсия (Tail Calls)

Недостатком рекурсии является риск бесконечных вызовов. Поэтому в elem_exists() предусмотрено несколько условий выхода. Perl предупреждает о глубокой рекурсии сообщением "Deep recursion on subroutine" после примерно 100 вызовов.

Хвостовая рекурсия — это когда функция возвращает результат вызова самой себя без дополнительных операций. Пример кандидата на оптимизацию:

return elem_exists($item, @array[0 .. $midpoint]) if $item < $miditem;
return elem_exists($item, @array[$midpoint + 1 .. $#array]);

Perl сам по себе не оптимизирует хвостовую рекурсию. Однако можно использовать специальную форму goto для замены текущего вызова:

if ($item < $miditem) {
    @_ = ($item, @array[0 .. $midpoint]);
    goto &elem_exists;
} else {
    @_ = ($item, @array[$midpoint + 1 .. $#array]);
    goto &elem_exists;
}

Такой приём помогает избежать чрезмерного расхода памяти при глубокой рекурсии.

Подводные камни и особенности

Старый стиль вызова функций

Perl по-прежнему поддерживает устаревший синтаксис вызова функций с амперсандом &:

# старый стиль — избегать
my $result = &calculate_result( 52 );

# очень старый стиль — категорически избегать
my $result = do &calculate_result( 42 );

Использование амперсанда отключает проверку прототипов и автоматически передаёт @_, что может привести к неожиданным эффектам.

Отсутствие скобок

Если опустить скобки при вызове функции, Perl может неправильно интерпретировать код. Пример с потенциальной ошибкой:

# потенциальная ошибка
ok elem_exists 1, @elements, 'found first element';

В этом случае строка 'found first element' будет ошибочно передана в elem_exists() вместо функции ok(). Это приведёт к скрытым ошибкам.

Вывод: разумное использование скобок улучшает читаемость кода и снижает риск ошибок.

Область видимости (Scope)

Всё, что имеет имя в Perl (переменная, функция, файловый дескриптор, класс), имеет свою область видимости. Она определяет продолжительность жизни и доступность сущности. Области видимости помогают инкапсулировать данные и избегать утечек реализации.

Лексическая область видимости

Лексическая область (lexical scope) — это та, что очевидна читателю. Любой блок в фигурных скобках создаёт новую область: { }, тело цикла, sub, eval, package и т.п.

Компилятор Perl разрешает лексическую область на этапе компиляции. Переменные, объявленные через my, видимы только внутри текущей области и вложенных в неё:

{
    package Robot::Butler;
    my $battery_level;

    sub tidy_room {
        my $timer;
        do {
            my $dustpan;
            ...
        } while (@_);

        for (@_) {
            my $polish_cloth;
            ...
        }
    }
}

$battery_level виден во всех четырёх областях. $timer — в методе и вложенных блоках. $dustpan — только в do-блоке, $polish_cloth — только в for.

Затенение переменных

Объявление переменной с тем же именем внутри вложенной области затеняет внешнюю:

my $name = 'Jacob';
{
    my $name = 'Edward';
    say $name; # Edward
}
say $name;     # Jacob

Это допустимо и иногда полезно, но может привести к путанице. Лучше ограничивать области переменных.

Интересный случай — for my $var: переменная объявляется вне блока, но область действия — внутри блока:

my $cat = 'Brad';
for my $cat (qw( Jack Daisy Petunia Tuxedo Choco )) {
    say "Внутренний кот: $cat";
}
say "Внешний кот: $cat";

Функции — именованные и анонимные — также создают лексические области. Это основа замыканий (Closures).

Область our

our объявляет псевдоним для глобальной переменной пакета. Само имя будет доступно повсюду (через полное имя), но псевдоним — только в пределах лексической области:

our $VERSION = '1.0';

Это полезно, например, для $VERSION или $AUTOLOAD. Совместимо с strict 'vars'.

Динамическая область (dynamic scope)

В отличие от лексической, динамическая область определяет видимость через стек вызовов. Она применима только к глобальным переменным (our), а не к my.

our $scope;

sub inner {
    say $scope;
}

sub middle {
    say $scope;
    inner();
}

sub main {
    say $scope;
    local $scope = 'main() scope';
    middle();
}

$scope = 'outer scope';
main();
say $scope;

В этом примере значение $scope временно меняется через local и становится видимым во всех вызовах, пока активна main(). После выхода из неё значение возвращается.

Lexical-переменные хранятся в структуре lexpad, которая создаётся при каждом входе в область. Это позволяет функциям — особенно рекурсивным — иметь независимые переменные.

Package-переменные и функции хранятся в symbol table пакета. Импорт и local работают с ней, и поэтому нельзя локализовать my-переменные — только глобальные.

local особенно полезен с магическими переменными:

  • $/ — разделитель строк ввода
  • $! — последняя ошибка системы
  • $@ — ошибка последнего eval
  • $| — автофлаш вывода

Ограничивайте область local как можно уже, чтобы избежать побочных эффектов.

Область видимости state

Ключевое слово state позволяет объявлять лексические переменные с однократной инициализацией и сохранением значения между вызовами функции:

sub counter {
    state $count = 1;
    return $count++;
}

say counter();
say counter();
say counter();

Вывод: 1, 2, 3. Если заменить state на my, результат будет 1, 1, 1.

Можно задать начальное значение через выражение:

sub counter {
    state $count = shift;
    return $count++;
}

say counter(2);
say counter(4);
say counter(6);

Результат будет: 2, 3, 4 — потому что shift срабатывает только один раз, при первом вызове.

Чтобы избежать нежелательного потребления аргументов, можно переписать:

sub counter {
    my ($initial_value, $text) = @_;
    state $count = $initial_value;
    say "Second arg is: $text";
    return $count++;
}

say counter(2, 'two');
say counter(4, 'four');
say counter(6, 'six');

Анонимные функции

Анонимная функция — это функция без имени. Она ведёт себя так же, как именованная: её можно вызывать, передавать ей параметры, возвращать значения и брать на неё ссылку. Единственный способ обратиться к ней — через ссылку.

Диспетчеризация (dispatch table)

Часто используется идиома, при которой хеш связывает команды с соответствующими функциями:

my %dispatch = (
    plus   => \&add_two_numbers,
    minus  => \&subtract_two_numbers,
    times  => \&multiply_two_numbers,
);

sub add_two_numbers      { $_[0] + $_[1] }
sub subtract_two_numbers { $_[0] - $_[1] }
sub multiply_two_numbers { $_[0] * $_[1] }

sub dispatch {
    my ($left, $op, $right) = @_;
    return unless exists $dispatch{ $op };
    return $dispatch{ $op }->( $left, $right );
}

Функция dispatch() может вызываться, например, как dispatch(2, 'times', 2) и вернёт результат 4.

Объявление анонимных функций

Если вызвать sub без имени — получится анонимная функция. Это удобно прямо внутри таблицы:

my %dispatch = (
    plus      => sub { $_[0] + $_[1] },
    minus     => sub { $_[0] - $_[1] },
    times     => sub { $_[0] * $_[1] },
    dividedby => sub { $_[0] / $_[1] },
    raisedto  => sub { $_[0] ** $_[1] },
);

Такой подход полезен, когда поведение простое и не требует повторного использования или отдельного определения.

Защищённая диспетчеризация (Defensive Dispatch)

В таблице диспетчеризации пользователь может вызвать только те функции, которые явно в ней указаны. Если же использовать переданную строку как имя функции напрямую, злоумышленник может вызвать любую функцию в любом пространстве имён:

dispatch('Internal::Functions::malicious_function');

Вызов анонимных функций как аргументов

Анонимные функции можно передавать как аргументы другим функциям:

sub invoke_anon_function {
    my $func = shift;
    return $func->( @_ );
}

sub named_func {
    say 'I am a named function!';
}

invoke_anon_function( \&named_func );
invoke_anon_function( sub { say 'Who am I?' } );

Имена анонимных функций

С помощью introspection (самоанализа кода) можно определить, является ли функция именованной или анонимной — например, с помощью caller() или модуля Sub::Identify:

package ShowCaller;

sub show_caller {
    my ($package, $file, $line, $sub) = caller(1);
    say "Called from $sub in $package:$file:$line";
}

sub main {
    my $anon_sub = sub { show_caller() };
    show_caller();
    $anon_sub->();
}

main();

Результат будет примерно такой:

Called from ShowCaller::main in ShowCaller:anoncaller.pl:20
Called from ShowCaller::__ANON__ in ShowCaller:anoncaller.pl:17

__ANON__ указывает, что функция анонимна и у неё нет имени, которое Perl может показать.

Присвоение имени анонимной функции

Модуль Sub::Name позволяет явно задать имя анонимной функции:

use Sub::Name;
use Sub::Identify 'sub_name';

my $anon = sub {};
say sub_name( $anon );

my $named = subname( 'pseudo-anonymous', $anon );
say sub_name( $named );
say sub_name( $anon );
say sub_name( sub {} );

Вывод будет примерно такой:

__ANON__
pseudo-anonymous
pseudo-anonymous
__ANON__

Важно: все ссылки на одну и ту же функцию указывают на одно и то же место в памяти. Переименование одной из них через subname() влияет на все остальные.

Неявные анонимные функции

Perl позволяет передавать анонимные функции без ключевого слова sub, например, в функциях с прототипами (см. map, eval). Это позволяет писать "отложенные" вызовы, которые выглядят не как обычные функции.

Пример с использованием модуля Test::Fatal:

use Test::More;
use Test::Fatal;

my $croaker = exception { die 'I croak!' };
my $liver   = exception { 1 + 1 };

like $croaker, qr/I croak/, 'die() should croak';
is $liver, undef, 'addition should live';

done_testing();

Эквивалентный более явный вариант:

my $croaker = exception( sub { die 'I croak!' } );
my $liver   = exception( sub { 1 + 1 } );

Или с передачей ссылок на именованные функции:

sub croaker { die 'I croak!' }
sub liver   { 1 + 1 }

my $croaker = exception \&croaker;
my $liver   = exception \&liver;

НО: нельзя передавать ссылку из переменной — это вызовет ошибку:

my $croak_ref = \&croaker;
my $live_ref  = \&liver;

# НЕ РАБОТАЕТ
my $croaker = exception $croak_ref;
my $liver   = exception $live_ref;

Ошибка от Perl будет: Type of arg 1 to ... must be block or sub {}.

Также нельзя оставлять запятую после блока:

dies_ok { die 'Boom!' } 'тест';

Такая особенность — результат парсера Perl, поэтому используйте аккуратно и обязательно документируйте поведение API.

Замыкания (Closures)

Замыкание — это функция, использующая лексические переменные из внешней области видимости. Даже если функция анонимная, она "запоминает" окружение, в котором была создана.

Создание замыканий

Простой пример:

my $filename = shift @ARGV;

sub get_filename {
    return $filename;
}

get_filename() использует лексическую переменную $filename, находящуюся вне тела функции.

Более интересный пример — создание итератора:

sub make_iterator {
    my @items = @_;
    my $count = 0;
    return sub {
        return if $count == @items;
        return $items[ $count++ ];
    }
}

my $cousins = make_iterator(qw(
    Rick Alex Kaycee Eric Corey Mandy Christine Alex
));

say $cousins->() for 1 .. 6;

Даже после выхода из make_iterator(), возвращённая функция сохраняет доступ к @items и $count — благодаря замыканию.

Каждый вызов make_iterator() создаёт отдельное окружение:

my $aunts = make_iterator(qw(
    Carole Phyllis Wendy Sylvia Monica Lupe
));

say $cousins->();
say $aunts->();

Таким образом, переменные инкапсулированы, и доступны только функции-замыканию.

Это можно использовать для защиты переменных:

{
    my $private_variable;
    sub set_private { $private_variable = shift }
    sub get_private { $private_variable }
}

Обратите внимание: именованные функции имеют глобальную область пакета, поэтому их нельзя вкладывать друг в друга. Вложенные функции не будут делить одну область, и Perl предупредит вас об этом.

Нарушение приватности

Модуль CPAN PadWalker позволяет нарушить лексическую инкапсуляцию. Но тот, кто это делает — сам и чинит возможные баги.

Практическое применение замыканий

Замыкания полезны не только при итерации по небольшим спискам. Например, вы можете генерировать значения последовательности Фибоначчи "по запросу", не храня все значения в памяти:

sub gen_fib {
    my @fibs = (0, 1);
    return sub {
        my $item = shift;
        if ($item >= @fibs) {
            for my $calc (@fibs .. $item) {
                $fibs[$calc] = $fibs[$calc - 2] + $fibs[$calc - 1];
            }
        }
        return $fibs[$item];
    }
}

my $fib = gen_fib();
say $fib->(42);

Функция запоминает уже вычисленные значения и пересчитывает только новые.

Обобщение кэширующего поведения

Можно выделить поведение кэширования в отдельную функцию и использовать её с разными алгоритмами:

sub gen_caching_closure {
    my ($calc_element, @cache) = @_;
    return sub {
        my $item = shift;
        $calc_element->($item, \@cache) unless $item < @cache;
        return $cache[$item];
    };
}

sub gen_fib {
    my @fibs = (0, 1, 1);
    return gen_caching_closure(sub {
        my ($item, $fibs) = @_;
        for my $calc ((@$fibs - 1) .. $item) {
            $fibs->[$calc] = $fibs->[$calc - 2] + $fibs->[$calc - 1];
        }
    }, @fibs);
}

Такой подход разделяет логику кэширования и логику вычисления, повышая читаемость и переиспользуемость.

Частичное применение (Partial Application)

Если функция всегда вызывается с одними и теми же аргументами, их можно зафиксировать через замыкание:

sub make_sundae {
    my %args = @_;
    ...
}

my $make_cart_sundae = sub {
    return make_sundae(@_,
        ice_cream => 'French Vanilla',
        banana    => 'Cavendish',
    );
};

Теперь достаточно передавать только переменные части заказа. Для подключения такой функции в другой модуль можно использовать Sub::Install.

Сравнение: state против замыкания

Оба подхода используют лексическое окружение:

{
    my $safety = 0;
    sub enable_safety  { $safety = 1 }
    sub disable_safety { $safety = 0 }
    sub do_something_awesome {
        return if $safety;
        ...
    }
}

Все функции используют одну переменную $safety, инкапсулированную снаружи. Но если переменная нужна только одной функции — проще использовать state:

sub serve_customer {
    state $cust_count = 0;
    $cust_count++;
    my $order = shift;
    add_sprinkles($order) if $cust_count % 100 == 0;
}

state также работает в анонимных функциях:

sub make_counter {
    return sub {
        state $count = 0;
        return $count++;
    }
}

Хотя здесь преимущества не столь очевидны.

state против псевдо-state

Раньше в Perl можно было сохранять значение my-переменной между вызовами через "обман" компилятора, используя if 0:

sub old_way {
    my $cached if 0;
    $cached++;
    return $cached;
}

Сейчас это считается плохой практикой. Лучше использовать state.

Устаревшие трюки с инициализацией

Использование постфиксного условия с my переменными теперь вызывает предупреждение о депрекации. Лучше использовать state:

sub inadvertent_state {
    state $counter = 1; # вместо my $counter = 1 if 0;
}

Атрибуты

Переменные и функции могут иметь атрибуты:

my $fortress :hidden;
sub erupt_volcano :ScienceProject { ... }

Они обрабатываются соответствующими хендлерами. Например, :Test в Test::Class:

sub setup_tests :Test(setup) { ... }
sub test_monkey_creation :Test(10) { ... }
sub shutdown_tests :Test(teardown) { ... }

Это позволяет чётко разделить роли методов без конфликта имён.

Минусы атрибутов

  • Плохая читаемость
  • Непредсказуемость поведения
  • Могут изменять семантику функции (например, :memoize)

Лучше использовать Attribute::Handlers или Attribute::Lexical, чем стандартный attributes.

AUTOLOAD

Если функция не определена, и вызов её не удаётся — Perl вызовет AUTOLOAD():

sub AUTOLOAD {
    our $AUTOLOAD;
    say "In AUTOLOAD(@_) for $AUTOLOAD!";
}

Можно извлечь имя метода и вернуть подставное значение:

sub AUTOLOAD {
    my ($name) = our $AUTOLOAD =~ /::(\w+)$/;
    return 'mu';
}

Делегирование через AUTOLOAD

Используется, чтобы проксировать вызовы, например для логирования:

sub AUTOLOAD {
    my ($name) = our $AUTOLOAD =~ /::(\w+)$/;
    Log::method_call($name, @_);
    my $self = shift;
    return $$self->$name(@_);
}

Генерация методов

Вместо постоянного попадания в AUTOLOAD, можно "устанавливать" метод в таблицу символов:

sub AUTOLOAD {
    my ($name) = our $AUTOLOAD =~ /::(\w+)$/;
    my $method = sub { ... };
    no strict 'refs';
    *{$AUTOLOAD} = $method;
    return $method->(@_);
}

Или использовать goto для замены вызова (tailcall):

sub AUTOLOAD {
    my ($name) = our $AUTOLOAD =~ /::(\w+)$/;
    my $method = sub { ... };
    no strict 'refs';
    *{$AUTOLOAD} = $method;
    goto &$method;
}

Проблемы AUTOLOAD

  • Метод can() не покажет, что функция существует
  • Может случайно перехватить DESTROY, если он не определён
  • Может конфликтовать с import, VERSION, unimport
  • Приводит к сложному коду и плохой отладке

Лучше всего заранее определить список методов через use subs:

use subs qw( red green blue );

Или переопределить can() для динамического определения метода:

sub can {
    my ($self, $method) = @_;
    return $self->SUPER::can($method) || do {
        return unless $self->should_generate($method);
        my $meth_ref = sub { ... };
        no strict 'refs';
        *{$method} = $meth_ref;
        return $meth_ref;
    };
}

sub AUTOLOAD {
    my ($self) = @_;
    my ($name) = our $AUTOLOAD =~ /::(\w+)$/;
    return unless my $meth_ref = $self->can($name);
    goto &$meth_ref;
}

Если Perl жалуется на inherited AUTOLOAD for non-method — значит, вы вызвали функцию в пакете, унаследованном от класса с AUTOLOAD.

Итог: AUTOLOAD полезен для быстрых решений, но сложен в сопровождении. Лучше избегать его в серьёзных проектах.
